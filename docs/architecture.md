# KoeStudio architecture notes

Detailed notes per area, kept in step with the code. `CLAUDE.md` holds the rules that apply everywhere (how painting works, the GPU rules, conventions); read the section here before changing an area, and update it when you change how that area works.

## Server and desktop window (`app.py`)

- **`app.py`**: stdlib `ThreadingHTTPServer` on 127.0.0.1 (port 8770, or the next free one) serving `web/` and a small JSON API, shown in a pywebview (WebView2) window. Flags: `--browser` (serve only), `--hidden` (window never shown), `--muted`. Env: `KOE_ART_DIR`, `KOE_APP_DIR`, `KOE_PORT`, `KOE_MUTE`.
- **Backups:** `save_art` (and rename) call `_keep_backup` first: when the newest kept version is older than `BACKUP_EVERY` (10 min) the file about to be replaced is hard-linked (or copied) to `.backups/<id>-<time>.koe`, keeping `BACKUP_KEEP` (5). The gallery opens a backup as a new artwork, never over the original.
- `do_POST` always consumes the request body (`_drop_body`): an unread body stays in the kept-alive connection and the next request fails with 501.
- `Handler._allowed` refuses requests from other web pages (foreign `Host`, foreign `Origin`, `Sec-Fetch-Site` cross-site/same-site).
- Static files are sent `Cache-Control: no-cache` (revalidated, so a reload picks up edits); API answers `no-store`.
- **Saves send only changes:** a layer or mask picture may come as `"ref:<sha1 of its data URL>"` (`pic_key`; the browser's `Raster.pngHash`); `SAVE_CACHE` keeps the pictures of the last save, or of `art/file?edit=1` (`load_for_editing`), of the last few artworks to fill refs in, so the `.koe` written is whole as before. A ref the server lacks raises `MissingLayers` (409 `{missing: true}`) and `save()` in editor.js resends everything (`toJSON(delta)` with `have` = null). `editor.serverHas` = {id, keys} is what the server holds; it is replaced only after a save succeeds.
- API: `config`, `art` (list), `art/file`, `art/thumb`, `art/save` (new id when none given), `art/delete` (moves the file, thumbnail and gallery details to `.deleted/` as `<id>-<time>.*`), `art/rename`, `art/duplicate`, `art/backups` / `art/backup` (earlier versions), `deleted` / `deleted/thumb` / `deleted/restore`, `fs/list?path=` (folders, picture/project files and places for the file browser; empty path = Exports), `fs/mkdir`, `export?format=&dir=&mode=` (png, jpg, webp, gif, bmp, tga or koe; the body's signature is checked; saved in `dir`, an existing folder, or `Exports/` when empty; when the name is taken `mode` numbers it (default), answers 409 `{exists: true}` (`ask`) or overwrites (`replace`)), `open-file` (the `.koe` given on the command line, handed out once), `open-folder?sub=|path=`, `timelapse?id=` / `timelapse/frame?id=&n=` / `timelapse/add?id=` (JPEG signature checked) / `timelapse/clear?id=` (frames in `.timelapse/<id>/<n>.jpg`, at most `TIMELAPSE_MAX`; delete/restore move the folder along as `.deleted/<id>-<time>.timelapse`). `app.py <file.koe>` queues a project to open. `known_folder(name)` finds Pictures/Desktop/Documents/Downloads (shell known folders).
- **`.koe` double-click:** `tools\register_koe.ps1` registers the `.koe` type for the current user (`-Remove` undoes it). Explorer then runs `KoeStudio.exe "<file>"` (or `pythonw app.py "<file>"` when the launcher is missing); `app.py` queues it in `PENDING_OPEN`, `config` reports `openFile`, and `js/app.js` takes it from `GET open-file` (handed out once) and opens it as a new artwork, like Open image or project…. Each launch is its own window. `KoeStudio.exe` (committed prebuilt; source `tools\launcher\KoeStudio.cs`, rebuilt with `tools\build_launcher.ps1`, which runs the .NET Framework `csc.exe`; commit the exe after rebuilding, and close KoeStudio first or move the running exe aside, since a running exe can't be overwritten) is a tiny launcher that finds a Python install at start (the PythonCore registry keys, PATH, the usual install folders; only folders with a `Lib` folder and `python3XX.dll` or `pythonw.exe`, so never the install manager's `Python\bin` or WindowsApps aliases; those with pywebview first, then newest) and **runs Python inside its own process**: it loads `python3XX.dll`, sets `PYTHONHOME` to the install and calls `Py_Main(KoeStudio.exe, app.py, <args>)`. The window then belongs to KoeStudio.exe, so Task Manager, the taskbar and Open with show "KoeStudio" with the cow icon (with the alias, Task Manager listed it under "Python launcher (windowed)"). `sys.executable` is then KoeStudio.exe, so never start Python children through it. The server, the pywebview window and its message loop all run in that one process (its only child is WebView2's `msedgewebview2.exe`), so tools that recognise programs by process file name see KoeStudio.exe; check it with `GetWindowThreadProcessId` on the window titled "KoeStudio". Only when no install's dll loads (e.g. a 32-bit Python) does it start that install's `pythonw.exe app.py <args>` and wait for it; the window is then pythonw.exe's. pywebview's .NET (pythonnet) shares the launcher's .NET Framework runtime without trouble. It carries `web/icon.ico` (`/win32icon`; built `/platform:x64` because the dll must match the process; `AssemblyTitle("KoeStudio")` is the name Task Manager shows), so rebuild it after changing the icon. `register_koe.ps1` points the association at it and adds an `Applications\KoeStudio.exe` entry. Rerun `register_koe.ps1` if the folder moves.
- **Window placement:** `app.py` saves `{x, y, width, height, maximized}` (logical px) to `<app dir>\window.json` when the window closes (`window_placement` reads `GetWindowPlacement`, so a maximized window keeps its normal rectangle) and `window_options` restores it, sized within the minimum and the largest screen and centred when its top edge is on no screen now. `--hidden` windows never save.

## Start-up, saving and files

- `js/app.js`: start-up (mute, reload key) and switching between gallery and editor.
- Saving: `save()` in `editor.js` retries every `SAVE_RETRY` after a failure (one toast per failing spell); the status shows the save time on hover.
- `js/imageformats.js`: export formats (`EXPORT_FORMATS`), `sanitizeExportOptions`/`exportSize` for the Export dialog, and pure TGA/BMP/GIF encoders (median-cut palette + LZW); PNG/JPEG/WebP come from `canvas.toBlob`. `js/views/exporttools.js` (Editor mixin): `exportAs(format)` (with a format: straight PNG; without: the Export dialog, options kept in `koe.exportOpts`), `exportCanvas` (area, paper, scale: whole-number enlargements unsmoothed, reductions halved step by step), `saveProjectFile()` (the whole `doc.toJSON()` as a `.koe` where the file browser says), `writeExport` (asks before replacing; a vanished folder falls back to Exports). Folders are remembered in `koe.exportDir` / `koe.projectDir` (`''` = Exports). `js/views/filebrowser.js`: `browseFile({title, dir, name, ext})` resolves to `{dir, name}`; `joinPath`/`stripExt` are tested and `openEarlierVersion()`; `app.py` `export_image` checks the file signature per format.
- `js/views/gallery.js`: artwork cards with a ⋯ menu (open, rename, duplicate, earlier versions, delete), the Deleted dialog (restore), `versionsDialog` (also used by File → Earlier versions…, which reopens through `onOpen`), New canvas dialog (`PRESETS`), Open image or project (a `.koe` file becomes a new artwork; an image becomes a one-layer canvas). The search box and sort list come from `galleryOrder` (`js/galleryorder.js`, tested) over `root.galleryList`; delete and rename update that list too (`showCards` redraws). `modal`'s `onOpen(root, close)` gets a `close(value)` for buttons inside the body. Dialogs can stack (only the top one takes Esc/Enter); a field with `data-own-enter` handles Enter itself.

## Editor core

- `js/views/editor.js`: the drawing screen. Viewport (`render`, `updateComp`), pointer input, painting, undo, autosave, menus and shortcuts (`onKey`). Feature groups live in mixins assigned to `Editor.prototype`: `layerops.js`, `selecttools.js`, `canvasops.js`.
- `js/doc.js`: `Doc` with a layer **tree** (`doc.root`, a `Folder`; `doc.active` is the selected node), `Layer` and `Mask` (both rasters: canvas, `version`, cached PNG), `Folder`, `cloneNode`, `nodeRasters`, `composite()` (paper, folders, "Through" pass-through, blend modes, opacity, clipping groups, masks, the live stroke), save format and `sanitizeDoc`. A picture the browser cannot decode loads as an empty raster (`loadPng` returns false; `doc.unreadable` lists the names and the editor warns on open) and keeps its saved `png`/`pngVersion`, so it is written back unchanged until painted on.
- `js/views/layerops.js`: everything that changes the tree (add, folder, Put in new folder, duplicate, delete, move/step, merge down, merge folder, properties), masks (add/apply/delete/toggle, mask editing), and the current-layer pixel operations (Move tool, clear, fill, flip).
- `js/views/canvasops.js`: canvas size, image size, crop (tool and to selection), rotate canvas, as Editor methods. All go through `reshapeCanvas(label, w, h, paint)`, which gives every layer a new canvas and records one undo step that swaps the old canvases back (`setCanvasState` also resizes the composite/stroke canvases, resets the selection and fits the view). Use it for any future change of canvas size, and pass its `m` (old doc point → new, an affine `[a, b, c, d, e, f]`) so guides, perspective, symmetry and line/concentric rulers follow (`mapRulers` in rulers.js, via `rulersAlong`; Flip canvas passes `canvas = true` to `flipPixels`).
- **Resolution** (`js/resolution.js` pure): `doc.dpi` (saved, `sanitizeDpi`, 72 for older files; `PRESETS` carry one), shown by `showDocSize()` in the status bar's hover, set in New canvas and Image size (a dpi change is its own 'Resolution' step, no pixels change). Exports write it: `pngWithDpi` (pHYs after IHDR, own CRC), `jpegWithDpi` (JFIF density), `encodeBmp(..., dpi)`.
- **Picking layers on the canvas:** Layer → Find layer on canvas (`findLayerMode`, command `findLayer`, no default key) sets `this.canvasPick = this.findPick` so the next canvas click runs `pickLayerAt`; Esc or running it again stops (`stopFindLayer`), and the cursor is a crosshair meanwhile. With the Move tool, Ctrl+click selects the top layer with paint there (`pickLayerAt`) and starts moving it; right-click lists them (`layerMenuAt`). Both use `layersAt(p)` (layerops.js: `shownLayersTopFirst`/`clipBase` from tree.js, one-pixel reads, masks and clipping respected). The Move tool works on `moveParts()` (snapshots of `layerRasters()`), `shiftParts` draws them shifted, `recordMove` makes the undo step; arrow keys call `nudgeLayer` (with a selection: a move-only transform), and presses in a row update the same step (`this.nudge`, matched by history entry identity).
- **Canvas gestures** (`bindPointer`): Ctrl+Alt+drag with a sized tool is `brushsize` (circle fixed at the start, `drawBrushOutline(..., label)` shows the size); Space with Shift / Ctrl makes the `pan` gesture turn / zoom (`panDrag`, `how`); the eyedropper's `pick` gesture keeps `before` for `drawPickRing`. Alt+click on a layer eye is `showOnly` (`soloChange` in tree.js; `this.solo` restores). The brush outline follows the tip: squash/angle as an ellipse through the view matrix, an image tip as `tipOutline` (painter.js: the tip's edge, cached per size in 4% steps); tips that turn by themselves keep the circle. Transform handles scale about the middle with Alt (`dragHandle(..., fromCentre)`).
- **Layer lock, reference and draft:** `node.locked` / `node.reference` / `node.draft` (layers and folders, saved only when true). Draft nodes are drawn as hidden inside `withoutDrafts(fn)` (doc.js, a flag `drawChildren` reads), which `exportCanvas` and `compPixels` use; `layerExportParts` leaves them (and layers clipped to them) out. `target()` and `beginMove` refuse a node locked itself or by a folder around it (`lockedNode`). Fill and the wand take their area from `sampleData(sample, t)`: 'all' (composite), 'layer', or 'reference' (visible reference layers, or layers in reference folders); the old `sampleAll` tick migrates in `sanitizeSettings`. **Stay inside lines** (paint tools' `refStop`): `beginPaint` sets `live.inside = insideLinesClip(pt, size / 2)`, a doc-sized canvas of where the stroke may paint (`insideLines` in fill.js on `referencePixels()`: the open area round the start, line pixels being `isLinePixel` = alpha >= 128 and not near white, grown 2 px into the lines only; a start on a line uses the nearest open pixel within the brush radius), cached in `this.insideClip` while the reference pixels are the same array and the next start falls inside it; `liveSource` cuts the stroke to it like the dual brush, so showing and committing agree. Vector layers ignore it. `refRead` is kept when switching to a tool with `refStop`. **Colorize** (`js/colorize.js` pure, `js/views/colorizetool.js`): from hints, `colorize(ref, hint, w, h)` labels the open shapes (`labelShapes`, 4-connected), gives each hinted shape its hint colours that make up at least `HINT_SHARE` of its hint pixels (several: by distance within the shape), spreads into closed unhinted shapes through lines (majority per shape; shapes touching the canvas edge stay clear), then `UNDER_LINES` px into the lines (`finishColors`, shared). Without hints, `autoColorize` gives each closed shape of at least `MIN_SHAPE` of the canvas a colour of `schemeColors(scheme, seed, own)` (seeded with `seeded`; 'palette' uses the Color panel's palette), biggest first, choosing the colour its `shapeNeighbours` (shapes grown into the lines until they meet) use least. The dialog previews on a layer put in the tree outside the history (above the hint layer, or under the lowest reference layer for picked colours); its seed is a hidden field, so Auto actions record it, and OK records one step.
- **Touch:** `bindPointer` keeps `this.touches` (finger id → screen point). A second finger turns any gesture a finger began into a `touchview` gesture (a finger's paint stroke is dropped, other gestures end normally; pen/mouse gestures ignore fingers): `pinchView` (view.js) zooms, turns (after `TURN_DEAD`) and pans from the view and finger points at its start; lifting without moving within `TAP_MS` undoes (two fingers) or redoes (three).
- **Shortcut strip** (`js/views/striptool.js`, `js/strip.js` pure): `.ed-strip`, a column of `STRIP_BUTTONS` put into `.ed-body` beside `.ed-center`, or a row (`.bottom`) in `.ed-center` under the viewport, or floating (`.float`, absolute inside `.ed-viewport`, dragged by `.strip-grip` in `bindStripGrip`; `placeStrip` keeps it inside with `floatSpot`, also from `resize()`; `.row` when `flat`) (`applyStrip`; the viewport's ResizeObserver resizes the view). Buttons call editor methods (`stripRun`: `undo`, `redo`, `setSize(nextSize())`, `colors.swap`, `fit`; nothing while a gesture runs, like keys); repeat buttons repeat while held, others run on pointerup inside the button. The hold buttons set `this.held.alt` / `.space` while any finger is on them (`HoldTracker`); a finger there never reaches the overlay's handlers, so the pen's stroke and `this.touches` are untouched. `koe.strip` = {on: true/false/null, side: left/right/bottom/float, collapsed, x, y, flat}; with `on` null it shows once `koe.penSeen` is set (`notePenUsed`, the first non-mouse pointerdown on the canvas, applied at pointerup). Window blur and hiding/folding let go of the holds (`releaseStripHolds`); a keyboard Alt/Space keyup leaves them held while a finger still holds the button.
- **View extras:** `grayView` (a `grayscale(1)` filter on the composite draw), `tileView` (`drawTiles` draws the composite or its mip into the 8 neighbouring places before the canvas; forces full renders), `pixelGrid` (`drawPixelGrid` in the overlay from `PIXEL_GRID_ZOOM`, only the visible pixels; `koe.pixelGrid`). Grayscale and tile preview are per session, each with a chip at the top that turns it off.
- **Layer colour labels:** `node.label` (one of `LABELS` in `doc.js`, or null), saved with the node, set from the swatch row in the layer panel through `setLayerProp`. **Mask area overlay:** `maskTint()` in `editor.js` draws the active mask (plus the live stroke) in red over the composite while `maskEdit` is on and View → Show mask area (`koe.maskOverlay`) is ticked; it is cached by mask version and `strokeVersion`.
- **Menus** (`menu(button, items, {onSide})` in ui.js): an item with `sub: [...]` is a submenu (opens on hover after 140 ms, click or →; disabled when none of its items is enabled). One menu is open at a time (`openMenuOwner()`); clicking its button again closes it. While open, a capture-phase keydown handles ↑ ↓ → ← Esc Enter and lets other keys through. The editor's menu bar (`openBar`) switches menus on hover while one is open and passes `onSide` so ← / → walk the bar. Keep each menu short enough for a 720 px high window: group rarely used items in a submenu. App-wide preferences (theme, pen pressure, shortcut strip, keyboard shortcuts) go in the **Settings** menu (`settings` in `menuItems`), not under File or View; the gallery's Settings button shows the ones that work without an artwork open (theme, keyboard shortcuts). The tool bar turns into two columns (`.two-col`, set in `resize()`) when it would overflow.
- `js/views/navpanels.js`: the **History** panel (`renderHistory` from `history.steps`, once per frame via `history.onChange`; `historyGoTo(n)` closes open edits and calls `History.goTo`) and the **Navigator** (`paintNav` after every `render`: the view outline at once, the scaled composite at most every 300 ms; clicks re-centre the view by changing `panX/panY`). Both sit in `.ed-left` under the tool panel; the left column folds to a strip only when all its panels are folded.

- **Shortcuts** (`js/shortcuts.js` pure, `js/views/shortcutsdialog.js`): every key `onKey` runs is a command id in `COMMANDS` (with its default combos) or `tool:<id>` (default `TOOLS[].key`). `keyBindings()` turns `koe.shortcuts` ({id: [combo]}, replacing that id's defaults) into `binds` and a `table` (combo → ids), cached until Settings → Keyboard shortcuts… saves (`koe-shortcuts` event: the tool bar's tooltips refresh). `onKey` looks the combo up: tools first (`toolForCombo` takes turns among tools on one key), then the `acts` of the command. Menus pass their items through `withKeyLabels`, which rewrites a `key` label whose default belongs to a command (`menuKeyLabel`). `assignKey` takes a key from its old owner unless both are tools. Space, Alt, Esc, Enter, F1, F5/Ctrl+R, Ctrl+V and the arrows are `RESERVED`. A new keyboard command goes in `COMMANDS` and `acts`, not as a raw combo.

## Side panels and dialogs

- `js/views/colorpanel.js`, `js/views/layerpanel.js`: side panels. They change the document only through editor methods. The layer panel draws `panelRows()` (top first, indented), handles click-to-select (the mask thumbnail selects mask editing) and drag-and-drop (`moveNodeTo`). Ctrl/Shift+click picks several nodes (`editor.picked`, a Set including `doc.active`; `multiPicked()` gives the outermost ones bottom first via `outermost` in tree.js); delete, duplicate, up/down, drag (`moveNodesTo` / `moveNodes`), the eye, Put in new folder and merge (`mergePicked`) then work on all of them. `structural()` clears `picked` before running do/undo, which may pick nodes again. Layer panel settings go through `setPickedProp`; `.lp-picked` shows the count with an "Only this one" button.
- `js/views/help.js` with `js/guide.js`: the **Help menu**. `guideDialog()` (F1 on every screen via `app.js`, and the gallery's Guide button) shows the `GUIDE` pages with `searchGuide`; a page shows a picture with `<figure data-pic="name">`, filled in from `PICS` in `js/guidepics.js` (small themed SVG diagrams, styled under `.gp` in app.css; a test checks every picture exists and is used); `shortcutsDialog()` lists `toolShortcuts(TOOLS)` (with the keys in use) plus `SHORTCUTS`, and the user's own keys first; `aboutDialog()` shows `build_info()` from `app.py` (commit read straight from `.git`), the folders and the Python version.
- `js/views/selectionbar.js`: the **selection bar** under a selection (`placeSelectionBar` from `paintOverlay`, placed by `selectionBarSpot` in selection.js; hidden during gestures, transforms, quick mask and polygons; `koe.selBar`). `js/views/timelapsetools.js` with `js/timelapse.js`: **timelapse** (`doc.timelapse`, saved only when true): `captureTimelapse` after each successful `save()` sends `thumbCanvas(1280)` as JPEG (at most every `FRAME_GAP`); `exportTimelapse` loads frames by URL as `recordWebm` asks for them (frames may be promises) following `timelapsePlan` (even skipping to a maximum length, ending held 2 s), fitted into `videoSize` of the last frame. `recordWebm` (exporttools.js) plays them into a MediaRecorder on a `captureStream(0)` canvas in real time; the browser drops unchanged frames, so the closing frame changes one pixel slightly; headless Edge records nothing (only a header, refused as an error), so test it in the browser pane. The layer panel's find box (`findRows` in tree.js) lists matching nodes with their folders. Transform bar boxes go through `typedTransform` (transform.js).
- `js/views/reftools.js`: the **Reference window** (floating, `koe.refWin` = {open, x, y, w, h, id}; pictures in `<app dir>\references` as `<id>__<name>.<ext>` via `refs`, `refs/image`, `refs/add` (signature checked), `refs/delete` in app.py). Click picks a colour, drag pans, wheel zooms. `placeFloating`/`bindFloatingHead` are the shared helpers for floating windows. The Color panel's **palette** is `koe.palette` (`paletteAdd`/`sanitizePalette` in color.js). Fill's **Close gaps** is `closeGapFill` in fill.js (lines thickened by the gap with the chamfer distance, flood filled, grown back over the clicked colour).
- **Palette files** (`js/palettes.js` pure: `parsePalette` for .gpl / .aco v1-v2 / .ase / hex lists, `gplText`): the palette's ⋯ menu in colorpanel.js; exports go through the `export` route as format `gpl` (signature `GIMP Palette`). `PALETTE_MAX` is 256.
- **Colour wheel:** `koe.colorWheel` swaps the square and hue bar for `.cp-wheel` (`wheelLayout` / `wheelHit` in color.js: a hue ring, 0° at the top clockwise, round the SV square; a drag stays on the part it began on). **Eyedropper:** `settings.picker` {pickFrom: all/layer, average: '1'/'3'/'5'/'11'}; `pickAt` averages with `averageColor` (alpha-weighted) and renders a small square of the picture in memory. **Count** (brush Variation): `addStampPoint` and vector.js `strokeStamps` lay `count` dabs per step, each with its own `dabJitter`.
- **Mixing strip** (`.cp-mix`): `mixSteps(a, b, 9)` in color.js (OKLab, `rgbToOklab` / `oklabToRgb`); picking from it passes `set(hex, true)`, which keeps `mixEnds` so the strip does not move; any other change of the main colour clears them.
- **Themes** (`js/themes.js` pure: `THEMES`, each the nine base colours of `THEME_KEYS`; `contrast`): `applyTheme(id)` in ui.js sets them as CSS variables on `<html>` (`koe.theme`, applied first thing in app.js) and fires `koe-theme`; the editor then re-reads `--canvas-bg` and the ruler colours (`resize`). Guide pictures (`.gp`) keep fixed colours (they sit on white paper).
- **Colour sliders:** the Color panel's HSV/RGB slider rows (`SLIDER_CHANNELS`, `sliderValues`, `fromSlider`, `sliderStops` in color.js; mode in `koe.colorSliders`).

## Selections and transform

- `js/selection.js`: `Selection`, a doc-sized mask canvas with bounds and an outline for the marching ants; `combine(mode, draw)` adds/subtracts/intersects a shape; `clipCanvas(ctx, rect)` cuts a canvas down to it; `morph`/`feather` go through `alphaPlane()`/`setAlphaPlane()` and `maskops.js` (chamfer 3-4 distance transform for expand/shrink, `borderMask` = expanded minus shrunk, Gaussian blur for feather; the canvas edge counts as outside when shrinking).
- `js/views/selecttools.js`: selection tools (rectangle, ellipse, lasso, polygon, magic wand), selection commands (incl. expand/shrink/feather via `Selection.morph`/`feather`, and Color range: `colorRangeDialog` previews `colorRangeMask` (maskops.js) live in a `modal({ live: true, passClicks: true })`; while it is open `this.canvasPick` takes canvas clicks to pick the colour), copy/cut/paste and free transform, as methods mixed into `Editor.prototype`. The polygon tool keeps its corners in `this.poly` between clicks (no gesture); `changeSelection` and `selectTool` drop it, `onPolygonKey` handles Enter/Esc/Backspace.
- `js/views/quickmask.js`: **Quick mask** (Q). `this.quickMask` is a temporary `Mask` (not in the tree, alpha = selected) that `target()` and `layerRasters()` return first, so every tool, Fill, filters and the Move tool work on it; `maskTint()` shows it in red (with the live stroke). Turning it on moves the selection into it and clears the selection; turning it off makes it the selection again; both are history steps that keep the same raster, so the stroke patches in between undo/redo in order. `reshapeCanvas` resizes it along with the layers (its undo step swaps the quick mask's canvas back too).
- **Mesh transform** (`startMesh` in selecttools.js; `meshFromQuad`/`meshSurface`/`meshWarp`/`meshHit` in transform.js): `xf.mesh` = {n: 3, pts (4 x 4 doc points, row by row), start}; the points span a Catmull-Rom surface sampled `MESH_SUB` times per cell, each small cell drawn through its own homography (`drawMeshed`, once per frame via `setMesh`); the selection mask is bent the same way on apply. Distort and Mesh both read the lifted pixels with `readTransformSource`.

## Painting and brushes

- `js/painter.js`: draws dabs (anti-aliased circles for hard brushes, a pre-rendered gradient tip for soft ones, or a tip image tinted in the brush colour); every tip can be squashed, turned, turned at random and turned with the stroke (`dab(x, y, size, alpha, k)`, k = symmetric copy, so each copy follows its own direction). `registerTip`/`registerTexture` make library images usable as `'img:<id>'`.
- **Brush textures** (`textures.js` tiles, `textureFor(s)` in `painter.js`): paint tools set `live.texture = {tile, scale}`; the stroke canvas itself stays untextured and `liveSource(live, r)` in `doc.js` cuts the grain out of a scratch copy whenever the stroke is shown or committed, so the grain is applied once per stroke (never compounding) and stays anchored to the doc. Anything that draws `live.canvas` must go through `liveSource`. With `grainPressure` (the Pencil's default) the grain is in the dabs instead: `grainFor(s)` gives the `Painter` a `grain` tile and `textureFor` returns null; `Painter.grainDab` draws each dab into a scratch canvas at depth sqrt(density / full density) (`grain.full` is the brush's Density, so the depth follows pressure alone), subtracts the doc-anchored groove depth (alpha inverted with an opaque `xor`, groove added with `lighter`, inverted back), refills the colour (`source-in`) and lays it down at the dab's density. Grooves deeper than the dab reaches stay empty under any number of overlapping dabs, so pressure decides how much of the grain fills. Grain brushes keep a low Density (Pencil 0.45, min 0.1): about 1/spacing dabs overlap at each point, and a high density piles a light line up to black on the tooth tops (harsh dots instead of grey graphite). The editor, vector lines and the brush preview all pass `grainFor`. **Wet edges** (`wetEdges`, Watercolour and Marker): `wetFor(s)` gives `live.wet = {amount k, blur}` (blur a sixth of the size), and `liveSource` (`wetEdges` in doc.js) turns the stroke A into A(1-k) + 2k A(1-B), B being A blurred with `ctx.filter` (read with a 3-blur margin round r, so partial redraws match the whole): the middle gives paint to a rim just inside the edge. Like the texture it is applied once per stroke, so the editor, vector lines and the preview pass `wetFor` too. It needs an even stroke to find the edge, so Watercolour uses a high Density under a low Opacity (a low density leaves the sides of a stroke soft, since fewer dabs reach them). **Color mixing** (`mix`, `mixStretch`; `wetmix.js` pure): with `mix > 0` (not erasing, not on masks or vector layers) `beginPaint` gives the gesture `wet = {cache, copies}`, a PixelCache over the target layer (read tile by tile when first touched; the layer itself does not change until pen-up, so it is always the pen-down picture). `drawStamps` asks `wetColor` for each dab's colour: `averageUnder` samples up to 9 x 9 points under the dab (alpha-weighted), and a `WetPaint` per symmetric copy drags the picked-up colour along (keep = stretch per brush width, by distance, so spacing does not matter) and mixes it into the brush colour by `mix` times its cover. The colour goes to `Painter.dab` like colour jitter. The stroke does not mix with its own paint.
- **Dual brush:** a paint tool's `dualTip` (≠ 'none') makes `beginPaint` set `g.dual` (`dualBrush`: its own `StampPath` at `dualSize` x the brush size and `dualSpacing`, a black `Painter` with the dual tip into `this.dualCanvas`) and `live.dual`; `addDualStamps` dabs it (scatter, symmetry) for every smoothed point, and `liveSource` keeps the stroke only where the dual canvas has paint (`destination-in`), so showing and committing both see it. Vector lines keep `dualTip`/`dualSize`/`dualSpacing`/`dualScatter` in their brush and `renderVector` redraws the dual dabs from `dualStamps` (seeded, as the Brush settings preview). The Brush settings preview runs the same along its path; ABR `dualBrush` imports into it (the import result's `dual` image index).
- **Hard pixels:** a paint tool's `pixel` setting makes `Painter.dab` fill `pixelSpans(x, y, size)` (brush.js: whole-pixel rows of a pixel-art circle) instead of a tip; kept by vector lines too. **Export layers** (`exportLayers` in exporttools.js): the parts come from `layerExportParts` (a top-level node with the layers clipped to it, or every layer with a clipped one cut to its base; correction layers left out), each through `renderFolder` into a canvas-sized PNG, `<name>-NN-<layer>.png`.
- **QuickShape** (`js/quickshape.js` pure: `detectShape`, `shapePoints`, `adjustShape`): with a paint tool's `quickShape` on, `addPoint` keeps the raw path in `g.raw` and `watchHold` restarts a `HOLD_MS` timer whenever the pen moves more than `HOLD_PX`; when it fires `snapQuickShape` sets `g.quick` and `redrawQuickShape` restamps the stroke canvas from scratch (fresh `StampPath`, no smoothing, `g.vec` too) along the shape; later points only move `g.quick.to` (redrawn once per frame).
- **Tilt and speed** (`tiltFrom`, `dynamicsAt`, `dynamicsReach`, `mixPoint` in brush.js): `bindPointer`'s `penPoint` gives paint points `t` (pen tilt 0-1), `az` (lean direction, turned into a doc angle) and `v` (screen speed, evened out, 0-1 of `SPEED_FULL`); `Smoother` and `StampPath` carry them along through `mixPoint`. `addStampPoint` multiplies `st.k` / `st.f` by `dynamicsAt` and sets `st.a` (tip direction, passed to `Painter.dab` as `dir`) when `tiltAngle` is on; bounds grow by `dynamicsReach`. Vector lines drawn with a brush that `usesDynamics` keep them per point as `[x, y, p, t, v, az]` (vector.js `mix` blends them in resample/slice; `strokeStamps` applies `dynamicsAt`; points without them are neutral, so edits that drop them are safe). Procreate's speed settings import into `speedSize` / `speedFlow`.
- **Pen pressure curve** (`js/views/pressuretool.js`; `adjustPressure`, `PRESSURE_PRESETS`, `pressureFromStrokes` in brush.js): `this.pressureCurve` (`koe.pressureCurve`, null = as the pen gives it) is applied to pen pointers in `bindPointer`'s `pressure()`, before any tool sees the value.
- **Your own gradients** (`js/views/gradienteditor.js`; `sanitizeUserGradients`, `stopsFor`, `addStopAt`, `stopCss` in gradient.js): `koe.gradients` = [{id, name, stops: [{o, c ('#rrggbb' | 'main' | 'sub'), a}]}], named in the Gradient tool's `colors` as `'user:<id>'` (accepted by `applySettings`); always pass `this.userGrads()` to `gradientStops`.
- `js/views/gradienttool.js`: the Gradient tool (presets: `GRADIENT_PRESETS` in gradient.js, picked through the Colors choice; Dither runs `ditherData`, doc-anchored triangular noise, once on the stroke canvas at pen-up; Repeat/Mirror: `gradientReach` counts the copies needed to cover the area, `repeatStops` lays them out over one stretched gradient, at most 1000); it fills the stroke canvas (selection bounds or the whole canvas) and commits like a stroke, so opacity, alpha lock, masks and undo behave as for painting.
- **Brush library** (`js/views/brushtools.js`, `js/brushtip.js` pure): tip/texture images and saved brushes live in `<app dir>\brushes` (`brushes.json` + `<id>.png`; app.py routes `brushes`, `brushes/image`, `brushes/image/delete`, `brushes/presets`; every change goes through `_change_brushes` under `BRUSH_LOCK` and reads the index strictly, since simultaneous replaces fail on Windows and an unreadable index must never be overwritten with an empty one). Paint tools name images in `tip` / `texture` as `'img:<id>'` (accepted by `applySettings` in `tools.js`); a setting naming a missing image falls back to round / no texture. A preset is `{id, name, settings (BRUSH_KEYS), source}`; the tool remembers it in `preset`. Pressure curves (`sizeCurve`, `flowCurve`: [[x, y]], monotone cubic `curveAt` in `brush.js`) replace `gamma` for their channel; `stampAt(s, p)` gives a stamp's size and density from raw pressure. Per dab, `addStampPoint` adds `dabJitter` (scatter offset, size/density jitter) and `taperIn` (start taper by distance along the stroke) to the stroke's own stamps before `symmetryStamps`, so mirrored copies vary together. Colour jitter (`colorJitter` in brush.js, `shiftColor` in color.js) gives each stamp its own `c` (or, with `colorJitterStroke`, varies `g.color` once at pen-down); `Painter.dab(..., color)` re-tints its tip canvas when the colour changes, and vector lines replay per-dab colours from their seed in `strokeStamps`. Erasers and masks never vary. The end taper (`taperOut`) holds the last `taperOut` px of stamps back in `g.held` (`releaseHeld`, each stamp keeps its distance `d`); `endPaint` scales them by `taperOut(dist - d)` and draws them through `drawStamps`.
- **Built-in brushes** (`js/builtinbrushes.js`, pure): `BUILTIN_BRUSHES` = [{id: 'b-<name>', group, name, builtin: true, settings}] with complete settings (the Brush tool's defaults without its tapers, plus changes); `builtinBrushesFor(tool)` gives the Eraser the 'Eraser' group and the other paint tools the rest. A tool remembers one in `preset` like a saved brush (the 'id' setting accepts both forms); `presetById` in brushtools.js looks in both, the Brush row lists them in an optgroup per group above "Your brushes", and the ⋯ menu's update/rename/delete are off for them. The **Brushes window** (`renderBrushList` / `createBrushList` in brushtools.js, `koe.brushList` = {open, x, y, w, h, size: 's' | 'm' | 'l'}; `brushListGroups` in builtinbrushes.js groups and searches) shows the same brushes as rows with a sample stroke: `paintPreviewStroke` (shared with the Brush settings preview and the stroke strip under the Brush row, both drawn by `drawBrushPreview`) on the tool's settings with the brush applied (`applySettings`), cached in `this.brushThumbs` by tool, size, colour and settings (cleared when tip images load) and painted a few per frame by `drawBrushList`, which also runs on colour changes and after a resize (ResizeObserver). Arrow keys step through the filtered rows (`stepBrushList`); right-click gives `brushRowMenu`. `brushChanged(s, p)` (builtinbrushes.js) tells whether loading the brush again would change a setting it keeps; `markBrushChanged` puts the * on the Brush choice and the window's row. The **Bristles** tip (`'bristle'` in `TIPS`) is drawn like a tip image: `builtinTip` in painter.js paints `bristleDots()` (brushtip.js) into a 128 px mask once; `hasTipImage` counts it, so its reach is an image tip's.
- **Brush import** (`brushimport.py`, route `brushes/import?name=`): `import_brushes(filename, data)` → `{name, brushes: [{name, settings, tip, texture, notes}], images: [{kind, name, png (data URL), white}]}` (tip/texture index into images, so shared images are saved once). **Procreate** `.brush` / `.brushset`: a ZIP with per brush `Brush.archive` (NSKeyedArchiver plist, read with `plistlib` and `_unarchive`; some tools write a plain dict), `Shape.png` (white = paint: `white: True`, turned into a see-through tip by `whiteToAlpha` in the browser before saving) and `Grain.png`; `brushset.plist` gives order and name. A brush folder's `Reset/` (Procreate's original, for Reset brush) and `SubNN/` (the second brush of a combined brush, noted with its name) are not brushes of their own (`_procreate_extra`); a blank name becomes the set's name and a number. Procreate's setting names (`paintSize`, `plotSpacing`, `shapeScatter`, `dynamicsPressureSize`, ...) are undocumented, so every one is optional and range-checked. **Photoshop ABR** v1/v2 (brushes inline) and v6-10 (`8BIM` sections `samp` tips (8/16-bit, raw or PackBits), `patt` patterns in PSD layout, `desc` action descriptor with `Brsh` entries pointing at tips by `sampledData` id and textures by `Txtr.Idnt`). Tips become black PNGs whose alpha is the sample. Photoshop angles turn counter-clockwise (`tipAngle = -Angl`). **GIMP** `.gbr` (v1/v2 header, gray = alpha or RGBA's alpha), `.gih` (first cell only, noted), `.vbr` (generated round). **Krita** `.kpp` (a PNG whose `preset` text chunk is XML: `<param>`s, with `brush_definition` itself XML: auto brush `MaskGenerator` diameter/ratio/fade (fade 1 = hard), or a tip `filename` found in a `.bundle`'s `brushes/` or as base64 inside the preset) and `.bundle` (ZIP of `.kpp`s, told apart from Procreate by containing `.kpp` files); XML with a DOCTYPE/ENTITY is refused. Krita's colour smudge engine imports with Color mixing at its `SmudgeRateValue`; other Krita engines import as ordinary brushes with a note. Procreate `dynamicsMix` becomes `mix` and `dynamicsWetEdges` `wetEdges`; Photoshop's Wet edges tick (`Wtdg`) gives `wetEdges` 0.5. The import dialog (`importBrushFile` in brushtools.js, helpers in `brushpick.js`) registers the pack's images under temporary ids (`registerImage`) so each card draws the brush's real stroke with `paintPreviewStroke`, lazily through an IntersectionObserver and a per-frame budget, and forgets them when it closes; packs over `PICK_ALL_UP_TO` start with nothing picked. Every change goes through `setPresets(list)`, which saves at once, clears tools' `preset` for deleted brushes and deletes the tip/texture images only deleted brushes used (`orphanImages`; images used by a tool's current settings stay). Hidden groups (`koe.hiddenBrushGroups`, keys `hideKey`: `b:` built-in, `s:` saved) are left out of `brushListGroups` and the Brush choice, except the brush in use. A menu opened from a dialog sits above it (`body:has(.modal-back) > .menu`).

- `js/views/smudgetool.js`: **Smudge** (J, kind `smudge`): changes the layer directly per dab with `smudgeDab` (`smudge.js`, premultiplied mix, carried colour per symmetric copy), keeps a copy of the layer from pen-down, and on pen-up records one patch (putting back pixels outside the selection with `mixByMask`). **Lasso fill** (G cycles Fill → Gradient → Lasso fill): fills the drawn shape into the stroke canvas and commits it like a stroke.

Works like Smudge: straight onto the layer per dab, one patch on pen-up, selection mixed back with `mixByMask`; non-push modes repeat every `HOLD_MS` while the pen is held still. With the symmetry ruler each copy dabs too (push direction from the copy's own step; `symmetryFlips` makes mirrored copies twirl the other way).
- `js/views/retouchtool.js` with `js/retouch.js`: the **retouch tools** (kind `retouch`): **Blur** (J after Liquify), **Dodge** / **Burn** (O) and **Clone stamp** (S). Like Smudge they change the layer per dab (`mixDab` towards a source patch: `blurredPatch` read with a margin, or `copyRegion` of the clone source; `toneDab` for dodge/burn keeps alpha), keep a pen-down copy and record one patch on pen-up, mixing the selection back with `mixByMask`. Blur/Dodge/Burn follow the symmetry ruler. Ctrl+click sets `this.cloneSrc` ({x, y, offset}); the stroke reads `sampleData(s.sample)` taken at pen-down, so it never copies its own dabs; `aligned` keeps the offset between strokes; `drawCloneOverlay` shows the source.

## Special layers

- **Vector layers** (`js/vector.js` pure, `js/vectorlayer.js` renderVector, `js/views/vectortools.js`): a `Layer` with `vector` = {brushes, strokes} (strokes: smoothed pen path `pts` [[x, y, p]] resampled to 1-4 px, brush index, colour, opacity, seed). Like text layers, its pixels are always `renderVector(layer)` and the PNG is saved too (loading uses the PNG). Vector objects are immutable: every edit makes a new one, `showVector(layer, from, to)` redraws `changedBounds`, `pushVectorStep` records it. `target(verb, { vector: true })` lets pens, the Eraser and Figure outlines through; everything else is refused with a Rasterize offer; `textsIn` drops vectors too (flip, canvas size, merge into). `beginPaint` collects `g.vec` (the points after the Smoother) and `endPaint` calls `commitVectorStroke` (one line per symmetric copy); the Eraser on a vector layer is a `verase` gesture running `eraseVector(v, settings.eraser.vectorErase, a, b, r)` per pointer move ('area' cuts points within r of the eraser; 'intersection' cuts a touched line between its nearest crossings with other lines, exactly at the crossings; 'line' removes touched lines; touched = within r of the painted edge). `strokeStamps` replays a line's dabs (spacing, tapers, seeded jitter) for rendering; Painter takes a seeded `rnd` for random tip turns. The Move tool translates the lines (`translateVector`). **Vector selection:** a selection takes the lines with at least half their points inside (`strokesInside` with `Selection.insideTest()`); Delete removes them (`removeStrokes`), Transform / Move-with-selection is `beginVectorTransform` (the lines lifted as pixels for the preview; apply maps their points with `mapStrokes`: affine scales `w` and turns `az`, Distort goes through `homography`; Mesh refused) recorded as one step that also restores the selection. A line may carry its own width factor `w` (0.1-5, not saved when 1); always look a line's brush up through `brushOf(v, s)`, which applies it. The **Line edit** tool (`js/views/lineedittool.js`, Y, kind `lineedit`): `nearestStroke` picks a line (`this.vline` = {layer, stroke}, found again by object identity so undo drops it), dragging pulls it with `pullStroke` (falloff over `settings.lineedit.reach`, resampled), the panel (`renderLineEditProps`) sets width/opacity/colour through `editStroke` (sliders preview, the change event records one step), Del removes it (`removeStroke`); Smooth runs `smoothStroke` (rounds of `smoothPoints`, ends and pressure kept).
- `js/views/texttool.js` with `js/textlayer.js`: **text layers** are ordinary `Layer`s with a `text` object (content, x, y, font, size, bold, italic, align, leading, colour, vertical, outline px and outlineColor hex; the Text tool's `outlineColor` setting is white/black/sub, turned into a hex by `outlineHex`); their pixels are always `renderTextLayer(layer)` of it, and the PNG is saved too. Editing uses a textarea in a `.text-edit` box that carries the view's CSS `matrix()`, so it follows zoom/rotation; its own text is transparent and the layer renders live underneath. Anything that changes a text layer's pixels directly must keep the text in step: `target()` refuses text layers (offering Rasterize) unless `{ read: true }`; the Move tool shifts `text.x/y`; whole-canvas changes, flips and merging into a text layer call `textsIn(rasters)` to drop the text (and restore it on undo). `finishText()` closes an open edit (switching tools, menus, saving, reloading). A text may carry `runs` ([{from, to, font?, size?, bold?, italic?, color?}], string indices, only what differs from the text's own settings; `sanitizeRuns`, `styleRange`, `editContent` keeps them in step with typing via the common prefix/suffix, `restyleText` for whole-text changes, `styleAt`): `layoutText(t, measure(str, st))` lays out pieces of one style (lines as tall as their biggest letters, smaller ones lowered by `ASCENT` onto the baseline; vertical columns advance per character size) and glyphs carry `st`. While editing, panel changes and the colour go to the textarea's selected characters (`textSelection`), else only the changed key goes to the whole text; `syncTextPanel` shows the look under the caret. The textarea itself uses the base font, so its caret drifts over mixed sizes. A text may carry `m` (a shear-free affine from layout space to the doc, `sanitizeTextMatrix`): `renderTextLayer` draws under it, hit tests go through `toTextLocal`, the editor box composes it with the view. Transform on a text layer is `beginTextTransform` (box = layout bounds placed by `textTransformStart`; apply stores `textMatrixAfter`, an undo step; Distort/Mesh refused); the Move tool shifts `m` when present. `textsIn(rasters, m)` maps text through `textAfterMap` (flips, quarter turns, image size, crop) and drops it only when that would shear; vector lines follow plain shifts.
- **Screentone** (`tone.js`, `js/views/tonetools.js`): a layer with `tone` ({cell, angle, shape, color}) keeps its gray pixels; `drawNode` in `composite()` turns the region being drawn into dots (`applyTone`, grid anchored to the doc), so thumbnails show gray but the canvas, flatten and export show dots. Merge down and Rasterize screentone use `tonedCanvas(layer)`. A tone may carry `x`/`y` (grid shift, kept only when not 0); the dialog sets the spacing in px or lines per inch at `doc.dpi` (`toneLpi`/`cellForLpi`), and New screentone can fade between two densities (`toneFadeLine`, a linear gradient of grays).
- **Correction layers** (`js/adjust.js`, `js/views/adjusttools.js`): a `Layer` with `adjust` = {type, params} (`ADJUSTMENTS`: the per-pixel filters of filters.js plus a gradient map with resolved `stops`; immutable, saved, `sanitizeAdjust`). Its canvas stays empty; `drawAdjust` in `composite()` copies what ctx already holds in r (read where ctx's transform puts it, so scaled thumbnails work) through a GPU SVG filter (`adjustFilter`: `adjustSpec` steps → `<filter>` with feColorMatrix / feComponentTransfer tables, cached per object and per spec) into a scratch, cuts its mask, and draws it back with `source-atop` (Normal) and the layer opacity; clipped, it changes the clipping group so far. Per-channel corrections reuse the filters' LUTs exactly; HSL uses a gray-axis hue rotation and mean-based saturation (close, not identical). `target()` refuses it (its mask works); Merge down bakes it into the layer below.
- **Layer color** (`node.layerColor`, '#rrggbb' or null, layers only, saved when set; `layerColorDialog` / `rasterizeLayerColor` in effecttools.js): `layerImage` in doc.js fills the region `source-atop` with it (`colorPaint`) after the live stroke and tone and before the mask, so the GPU does it with no readback; `drawNode` routes such layers through `layerImage`, kept looks are keyed on it, and `tonedCanvas` bakes it in for merge down.
- **Layer effects** (`js/effects.js` pure, `js/views/effecttools.js`): a layer's `effects` = {border: {size, color}, shadow: {x, y, blur, color, opacity}} (`sanitizeEffects`, saved only when set). `drawNode` in `composite()` builds the layer (via `layerImage`) for r grown by `effectReach` and draws `effectsImage` (shadow from the paint plus border, then the border) under it; `updateComp` grows every dirty rectangle by `docEffectReach(doc)` so partial redraws still equal full ones. Merge down bakes them in (`effectsCanvas`); Layer → Rasterize layer effects does it on its own. The dialog previews by setting `node.effects` live, then records one `setLayerProp` step.

## Rulers, symmetry and figures

- `js/views/rulertools.js`: edge rulers, guides, perspective ruler (1-3 vanishing points), the grid (`doc.rulers.grid` = {show, size, div, snap}: `drawGrid`, `toggleGrid` Ctrl+', `gridDialog`; showing and settings are saved but not undo steps; grid snapping is its own opt-in because `rulers.snap` defaults on; `gridPoint(dp)` (`snapToGrid`, then `snapToGuides`, which wins) puts the corners of rectangle/ellipse/polygon selections, figures and crops on grid lines and shown guides within `GRID_SNAP_PX`) and stroke snapping, as Editor methods. The outline points come from `figurePoints`, the shape is re-stamped into the stroke canvas on every move (`figureDraw`, stamping through `stampOutline`) and committed with `commitStroke`. **Polyline/polygon** and **Curve/Closed curve** (`POLY_SHAPES`; `SMOOTH_SHAPES` run through `splinePoints`, a centripetal Catmull-Rom spline, when finished and in the overlay preview) are clicked: `this.figPoly` holds the corners between clicks (drawn on the overlay by `drawFigurePoly`, no gesture), `finishFigurePoly` stamps `polyCorners` (repeats dropped) and commits; tool switches and undo drop it, `onFigurePolyKey` handles Enter/Esc/Backspace. `linePoints` also serves Shift+click straight strokes in `beginPaint` (from `this.lastStroke`).

## Pure, tested modules

- Pure, tested modules: `filters.js` (blur via three box blurs on premultiplied planes, sharpen, mosaic, motion blur as a running-sum box blur along parallel pixel lines, zoom/spin blur (`pathBlur`: bilinear samples in the middle of up to 8 equal parts of each streak, later passes 1/8 as long filling the parts; the centre is a % of the canvas, so `apply` also gets the doc size `W, H` and their `margin` is the whole canvas), doc-anchored noise (`noiseAt`), LUT corrections incl. colour balance and Curves (`curvesLut` through `curveAt`; the dialog in `filtertools.js` is a canvas curve editor with a histogram, used when a filter has `curves: true` instead of slider `fields`), HSL, `mixByMask`, `recolor` (Change color to main color: filters with `mainColor: true` get `p.color`), `whiteToAlpha` (Brightness to opacity)), `maskops.js`, `tone.js` (tone sanitizing, density, `applyTone` with equalized spot functions so a density covers that share of the area), `textures.js` (seamless texture tiles), `textlayer.js` layout (`layoutText` with a measure function; vertical text runs in columns right to left), `gradient.js`, `rulers.js` (ruler sanitizing, tick steps, snap candidates/picking/projection, guide hit testing), `tree.js` (layer tree: listing, paths, `destination`/`moveNode` for above/below/top-of/bottom-of, `stepTarget` for the up/down buttons), `canvasmath.js` (anchor offsets, side limits, crop rectangles), `mips.js`, `pixelcache.js`, `transform.js` (free-transform maths: handles, scale about the opposite handle, rotate, hit testing), `brush.js` (pressure, curves, smoothing, stamp spacing), `brushtip.js` (tip masks and texture grays from images), `fill.js` (flood fill, or every matching pixel with `contiguous` off; grow), `history.js` (undo stack with step and memory limits), `view.js` (zoom/rotate/mirror maths), `tools.js` (tool list and settings), `color.js`, `rect.js`, `keys.js`.
