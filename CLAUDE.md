# KoeStudio

Windows desktop drawing and painting program, aiming to be a full-purpose tool in the spirit of Clip Studio Paint. See README.md for the user-facing feature list and the roadmap below for what comes next.

## Workflow (follow this in every session)

- **Runs straight from this folder.** The Desktop and Start-menu shortcuts (`KoeStudio.lnk`) and `Run KoeStudio.lnk` start `KoeStudio.exe` (a committed launcher, see the `.koe` double-click note), which runs `pythonw app.py` from the project folder. There is no installer and no build step for day-to-day use: every saved change is live the next time the app is opened, or straight away after a reload.
- **Reload key:** F5 or Ctrl+R in any screen saves pending work, then reloads the page so edited `web/` files take effect (`reload()` in `js/app.js`; the open screen and artwork are remembered in `sessionStorage`). Changes to `app.py` need the app restarted.
- **The user's data lives outside the project folder.** Artwork: `Pictures\KoeStudio` (`<id>.koe`, `.thumbs/`, `.backups/`, `.deleted/`, `Exports/`). Window storage (tool settings, colours) and `error.log`: `%LOCALAPPDATA%\KoeStudio`. Never write user data into the project.
- **Never build installers or release packages (nothing for others to install), and never publish a GitHub release, unless the user asks.** The committed `KoeStudio.exe` launcher is not one of these: it just starts `app.py`. Finish changes in source, run the tests, and commit.
- **Testing must not disturb the user:**
  - **Nothing pops up on the desktop.** Test the UI with `python app.py --browser` in Claude's built-in browser pane, or start the real window with `--hidden` (never shown). Don't launch the visible app while testing.
  - **Sound is muted.** Always start test runs with `KOE_MUTE=1` (or `--muted`). `js/mute.js` then silences every audio entry point (media elements, Web Audio, speech), so it also covers sound code added later. Any new sound must still play through the normal browser APIs so the mute catches it.
  - **Scratch data only.** Point test runs at a scratch folder, never the real `Pictures\KoeStudio`:
    `KOE_ART_DIR=<scratch>/art KOE_APP_DIR=<scratch>/app KOE_MUTE=1 KOE_PORT=8790 python app.py --browser`
  - **Looking at the UI:** `node tools/ui_shot.mjs <url> <steps.mjs> <out-folder> [w] [h]` drives a headless, muted Edge over the DevTools protocol and saves screenshots; nothing appears on the desktop. The steps module gets `evaluate(js)`, `shot(name)`, `wait(ms)`, `navigate(url)`. Keep step scripts and screenshots in the scratchpad, point the URL at a scratch test server, and read the PNGs to check layout changes before calling UI work done.
  - When the browser pane is hidden it may not paint or fire ResizeObserver, and its viewport can be 0×0. Give the tab a size with `resize_window` (e.g. 1400×900, reset to `desktop` afterwards), reload, drive it with `javascript_tool` (dispatch `PointerEvent`/`KeyboardEvent`; after Ctrl+0 the view is `zoom = min((vw-80)/W, (vh-80)/H)`, centred) and check results through the saved files (`.thumbs/<id>.png`).
- **`.koe` double-click:** `tools\register_koe.ps1` registers the `.koe` type for the current user (`-Remove` undoes it). Explorer then runs `pythonw app.py "<file>"`; `app.py` queues it in `PENDING_OPEN`, `config` reports `openFile`, and `js/app.js` takes it from `GET open-file` (handed out once) and opens it as a new artwork, like Open image or project…. Each launch is its own window. `KoeStudio.exe` (committed prebuilt; its small C# source is deliberately not kept, so write a new one when it must change) is a tiny launcher that finds `pythonw.exe` at start (PATH, the PythonCore registry keys, the usual install folders; never the WindowsApps alias), runs `app.py <args>` next to it and **waits for it**, so Windows lists KoeStudio in Open with and Task Manager shows Python under "KoeStudio" with the cow icon. It carries `web/icon.ico` (built with the .NET Framework `csc.exe`: `/target:winexe /win32icon:web\icon.ico /reference:System.Windows.Forms.dll`, `AssemblyTitle("KoeStudio")` for the name Task Manager shows), so rebuild it after changing the icon. `register_koe.ps1` points the association at it and adds an `Applications\KoeStudio.exe` entry. Rerun `register_koe.ps1` if the folder moves.
- **Window placement:** `app.py` saves `{x, y, width, height, maximized}` (logical px) to `<app dir>\window.json` when the window closes (`window_placement` reads `GetWindowPlacement`, so a maximized window keeps its normal rectangle) and `window_options` restores it, sized within the minimum and the largest screen and centred when its top edge is on no screen now. `--hidden` windows never save.
- If the folder or Python moves, recreate the shortcuts with `powershell -ExecutionPolicy Bypass -File tools\make_shortcut.ps1` (`-LocalOnly` makes only the one in the project folder).

## Architecture

- **`app.py`**: stdlib `ThreadingHTTPServer` on 127.0.0.1 (port 8770, or the next free one) serving `web/` and a small JSON API, shown in a pywebview (WebView2) window. Flags: `--browser` (serve only), `--hidden` (window never shown), `--muted`. Env: `KOE_ART_DIR`, `KOE_APP_DIR`, `KOE_PORT`, `KOE_MUTE`.
  - **Backups:** `save_art` (and rename) call `_keep_backup` first: when the newest kept version is older than `BACKUP_EVERY` (10 min) the file about to be replaced is hard-linked (or copied) to `.backups/<id>-<time>.koe`, keeping `BACKUP_KEEP` (5). The gallery opens a backup as a new artwork, never over the original.
  - `do_POST` always consumes the request body (`_drop_body`): an unread body stays in the kept-alive connection and the next request fails with 501.
  - `Handler._allowed` refuses requests from other web pages (foreign `Host`, foreign `Origin`, `Sec-Fetch-Site` cross-site/same-site).
  - Static files are sent `Cache-Control: no-cache` (revalidated, so a reload picks up edits); API answers `no-store`.
  - API: `config`, `art` (list), `art/file`, `art/thumb`, `art/save` (new id when none given), `art/delete` (moves the file, thumbnail and gallery details to `.deleted/` as `<id>-<time>.*`), `art/rename`, `art/duplicate`, `art/backups` / `art/backup` (earlier versions), `deleted` / `deleted/thumb` / `deleted/restore`, `fs/list?path=` (folders, picture/project files and places for the file browser; empty path = Exports), `fs/mkdir`, `export?format=&dir=&mode=` (png, jpg, webp, gif, bmp, tga or koe; the body's signature is checked; saved in `dir`, an existing folder, or `Exports/` when empty; when the name is taken `mode` numbers it (default), answers 409 `{exists: true}` (`ask`) or overwrites (`replace`)), `open-file` (the `.koe` given on the command line, handed out once), `open-folder?sub=|path=`. `app.py <file.koe>` queues a project to open. `known_folder(name)` finds Pictures/Desktop/Documents/Downloads (shell known folders).
- **`web/`**: vanilla ES modules, no framework, no build step. Edit and reload.
  - `js/app.js`: start-up (mute, reload key) and switching between gallery and editor.
  - `js/imageformats.js`: export formats (`EXPORT_FORMATS`), `sanitizeExportOptions`/`exportSize` for the Export dialog, and pure TGA/BMP/GIF encoders (median-cut palette + LZW); PNG/JPEG/WebP come from `canvas.toBlob`. `js/views/exporttools.js` (Editor mixin): `exportAs(format)` (with a format: straight PNG; without: the Export dialog, options kept in `koe.exportOpts`), `exportCanvas` (area, paper, scale: whole-number enlargements unsmoothed, reductions halved step by step), `saveProjectFile()` (the whole `doc.toJSON()` as a `.koe` where the file browser says), `writeExport` (asks before replacing; a vanished folder falls back to Exports). Folders are remembered in `koe.exportDir` / `koe.projectDir` (`''` = Exports). `js/views/filebrowser.js`: `browseFile({title, dir, name, ext})` resolves to `{dir, name}`; `joinPath`/`stripExt` are tested and `openEarlierVersion()`; `app.py` `export_image` checks the file signature per format.
  - Saving: `save()` in `editor.js` retries every `SAVE_RETRY` after a failure (one toast per failing spell); the status shows the save time on hover.
  - `js/views/gallery.js`: artwork cards with a ⋯ menu (open, rename, duplicate, earlier versions, delete), the Deleted dialog (restore), `versionsDialog` (also used by File → Earlier versions…, which reopens through `onOpen`), New canvas dialog (`PRESETS`), Open image or project (a `.koe` file becomes a new artwork; an image becomes a one-layer canvas). `modal`'s `onOpen(root, close)` gets a `close(value)` for buttons inside the body. Dialogs can stack (only the top one takes Esc/Enter); a field with `data-own-enter` handles Enter itself.
  - `js/views/editor.js`: the drawing screen. Viewport (`render`, `updateComp`), pointer input, painting, undo, autosave, menus and shortcuts (`onKey`). Feature groups live in mixins assigned to `Editor.prototype`: `layerops.js`, `selecttools.js`, `canvasops.js`.
  - `js/views/colorpanel.js`, `js/views/layerpanel.js`: side panels. They change the document only through editor methods. The layer panel draws `panelRows()` (top first, indented), handles click-to-select (the mask thumbnail selects mask editing) and drag-and-drop (`moveNodeTo`). Ctrl/Shift+click picks several nodes (`editor.picked`, a Set including `doc.active`; `multiPicked()` gives the outermost ones bottom first via `outermost` in tree.js); delete, duplicate, up/down, drag (`moveNodesTo` / `moveNodes`), the eye, Put in new folder and merge (`mergePicked`) then work on all of them. `structural()` clears `picked` before running do/undo, which may pick nodes again. Layer panel settings go through `setPickedProp`; `.lp-picked` shows the count with an "Only this one" button.
  - `js/doc.js`: `Doc` with a layer **tree** (`doc.root`, a `Folder`; `doc.active` is the selected node), `Layer` and `Mask` (both rasters: canvas, `version`, cached PNG), `Folder`, `cloneNode`, `nodeRasters`, `composite()` (paper, folders, "Through" pass-through, blend modes, opacity, clipping groups, masks, the live stroke), save format and `sanitizeDoc`.
  - `js/views/layerops.js`: everything that changes the tree (add, folder, Put in new folder, duplicate, delete, move/step, merge down, merge folder, properties), masks (add/apply/delete/toggle, mask editing), and the current-layer pixel operations (Move tool, clear, fill, flip).
  - `js/views/selecttools.js`: selection tools (rectangle, ellipse, lasso, polygon, magic wand), selection commands (incl. expand/shrink/feather via `Selection.morph`/`feather`, and Color range: `colorRangeDialog` previews `colorRangeMask` (maskops.js) live in a `modal({ live: true, passClicks: true })`; while it is open `this.canvasPick` takes canvas clicks to pick the colour), copy/cut/paste and free transform, as methods mixed into `Editor.prototype`. The polygon tool keeps its corners in `this.poly` between clicks (no gesture); `changeSelection` and `selectTool` drop it, `onPolygonKey` handles Enter/Esc/Backspace.
  - `js/views/filtertools.js` with `js/filters.js`: the **Filter menu**. `FILTERS` lists each filter with its dialog sliders, `margin(params)` (how far it reads outside the area, so blurs at a selection edge see their surroundings) and `apply(data, w, h, params, x0, y0, W, H)` (W, H: the doc size). `runFilter` takes `target()` (layer or mask), snapshots the whole raster, previews on every slider change (`previewFilter`: filter the area + margin, `mixByMask` with the selection's alpha, put back) in a non-dimming `modal({ live: true })` at the bottom, and on OK records one `pushPatch` for the selection bounds; Cancel restores the snapshot. Add a filter by adding an entry to `FILTERS` with a pure function and a test.
  - `js/views/navpanels.js`: the **History** panel (`renderHistory` from `history.steps`, once per frame via `history.onChange`; `historyGoTo(n)` closes open edits and calls `History.goTo`) and the **Navigator** (`paintNav` after every `render`: the view outline at once, the scaled composite at most every 300 ms; clicks re-centre the view by changing `panX/panY`). Both sit in `.ed-left` under the tool panel; the left column folds to a strip only when all its panels are folded.
  - `js/views/help.js` with `js/guide.js`: the **Help menu**. `guideDialog()` (F1 on every screen via `app.js`, and the gallery's Guide button) shows the `GUIDE` pages with `searchGuide`; a page shows a picture with `<figure data-pic="name">`, filled in from `PICS` in `js/guidepics.js` (small themed SVG diagrams, styled under `.gp` in app.css; a test checks every picture exists and is used); `shortcutsDialog()` lists `toolShortcuts(TOOLS)` plus `SHORTCUTS`; `aboutDialog()` shows `build_info()` from `app.py` (commit read straight from `.git`), the folders and the Python version.
  - **Vector layers** (`js/vector.js` pure, `js/vectorlayer.js` renderVector, `js/views/vectortools.js`): a `Layer` with `vector` = {brushes, strokes} (strokes: smoothed pen path `pts` [[x, y, p]] resampled to 1-4 px, brush index, colour, opacity, seed). Like text layers, its pixels are always `renderVector(layer)` and the PNG is saved too (loading uses the PNG). Vector objects are immutable: every edit makes a new one, `showVector(layer, from, to)` redraws `changedBounds`, `pushVectorStep` records it. `target(verb, { vector: true })` lets pens, the Eraser and Figure outlines through; everything else is refused with a Rasterize offer; `textsIn` drops vectors too (flip, canvas size, merge into). `beginPaint` collects `g.vec` (the points after the Smoother) and `endPaint` calls `commitVectorStroke` (one line per symmetric copy); the Eraser on a vector layer is a `verase` gesture running `eraseVector(v, settings.eraser.vectorErase, a, b, r)` per pointer move ('area' cuts points within r of the eraser; 'intersection' cuts a touched line between its nearest crossings with other lines, exactly at the crossings; 'line' removes touched lines; touched = within r of the painted edge). `strokeStamps` replays a line's dabs (spacing, tapers, seeded jitter) for rendering; Painter takes a seeded `rnd` for random tip turns. The Move tool translates the lines (`translateVector`). A line may carry its own width factor `w` (0.1-5, not saved when 1); always look a line's brush up through `brushOf(v, s)`, which applies it. The **Line edit** tool (`js/views/lineedittool.js`, Y, kind `lineedit`): `nearestStroke` picks a line (`this.vline` = {layer, stroke}, found again by object identity so undo drops it), dragging pulls it with `pullStroke` (falloff over `settings.lineedit.reach`, resampled), the panel (`renderLineEditProps`) sets width/opacity/colour through `editStroke` (sliders preview, the change event records one step), Del removes it (`removeStroke`); Smooth runs `smoothStroke` (rounds of `smoothPoints`, ends and pressure kept).
  - `js/views/reftools.js`: the **Reference window** (floating, `koe.refWin` = {open, x, y, w, h, id}; pictures in `<app dir>\references` as `<id>__<name>.<ext>` via `refs`, `refs/image`, `refs/add` (signature checked), `refs/delete` in app.py). Click picks a colour, drag pans, wheel zooms. `placeFloating`/`bindFloatingHead` are the shared helpers for floating windows. The Color panel's **palette** is `koe.palette` (`paletteAdd`/`sanitizePalette` in color.js). Fill's **Close gaps** is `closeGapFill` in fill.js (lines thickened by the gap with the chamfer distance, flood filled, grown back over the clicked colour).
  - `js/views/quickmask.js`: **Quick mask** (Q). `this.quickMask` is a temporary `Mask` (not in the tree, alpha = selected) that `target()` and `layerRasters()` return first, so every tool, Fill, filters and the Move tool work on it; `maskTint()` shows it in red (with the live stroke). Turning it on moves the selection into it and clears the selection; turning it off makes it the selection again; both are history steps that keep the same raster, so the stroke patches in between undo/redo in order. `reshapeCanvas` resizes it along with the layers (its undo step swaps the quick mask's canvas back too).
  - `js/selection.js`: `Selection`, a doc-sized mask canvas with bounds and an outline for the marching ants; `combine(mode, draw)` adds/subtracts/intersects a shape; `clipCanvas(ctx, rect)` cuts a canvas down to it; `morph`/`feather` go through `alphaPlane()`/`setAlphaPlane()` and `maskops.js` (chamfer 3-4 distance transform for expand/shrink, `borderMask` = expanded minus shrunk, Gaussian blur for feather; the canvas edge counts as outside when shrinking).
  - `js/views/canvasops.js`: canvas size, image size, crop (tool and to selection), rotate canvas, as Editor methods. All go through `reshapeCanvas(label, w, h, paint)`, which gives every layer a new canvas and records one undo step that swaps the old canvases back (`setCanvasState` also resizes the composite/stroke canvases, resets the selection and fits the view). Use it for any future change of canvas size, and pass its `m` (old doc point → new, an affine `[a, b, c, d, e, f]`) so guides, perspective, symmetry and line/concentric rulers follow (`mapRulers` in rulers.js, via `rulersAlong`; Flip canvas passes `canvas = true` to `flipPixels`).
  - **Brush textures** (`textures.js` tiles, `textureFor(s)` in `painter.js`): paint tools set `live.texture = {tile, scale}`; the stroke canvas itself stays untextured and `liveSource(live, r)` in `doc.js` cuts the grain out of a scratch copy whenever the stroke is shown or committed, so the grain is applied once per stroke (never compounding) and stays anchored to the doc. Anything that draws `live.canvas` must go through `liveSource`.
  - **Screentone** (`tone.js`, `js/views/tonetools.js`): a layer with `tone` ({cell, angle, shape, color}) keeps its gray pixels; `drawNode` in `composite()` turns the region being drawn into dots (`applyTone`, grid anchored to the doc), so thumbnails show gray but the canvas, flatten and export show dots. Merge down and Rasterize screentone use `tonedCanvas(layer)`.
  - `js/views/figuretool.js` with `js/figure.js`: the **Figure tool** (line, rectangle, ellipse; Shift constrains). The outline points come from `figurePoints`, the shape is re-stamped into the stroke canvas on every move (`figureDraw`, stamping through `stampOutline`) and committed with `commitStroke`. **Polyline/polygon** and **Curve/Closed curve** (`POLY_SHAPES`; `SMOOTH_SHAPES` run through `splinePoints`, a centripetal Catmull-Rom spline, when finished and in the overlay preview) are clicked: `this.figPoly` holds the corners between clicks (drawn on the overlay by `drawFigurePoly`, no gesture), `finishFigurePoly` stamps `polyCorners` (repeats dropped) and commits; tool switches and undo drop it, `onFigurePolyKey` handles Enter/Esc/Backspace. `linePoints` also serves Shift+click straight strokes in `beginPaint` (from `this.lastStroke`).
  - **Symmetry ruler** (`symmetry.js` pure: `symmetryPoints`/`symmetryStamps`/`symmetryRays`; `js/views/symmetrytools.js`: overlay, dialog, centre handle dragged by the Ruler tool as a `vp` gesture with `index: 'sym'`): `doc.rulers.symmetry` = {kind, lines, x, y} (null centre = canvas middle), changed through `editRulers`. Paint tools pass their stamps through `symmetryStamps` in `addStampPoint`; Smudge and Lasso fill do the same. New drawing tools should too.
  - `js/views/smudgetool.js`: **Smudge** (J, kind `smudge`): changes the layer directly per dab with `smudgeDab` (`smudge.js`, premultiplied mix, carried colour per symmetric copy), keeps a copy of the layer from pen-down, and on pen-up records one patch (putting back pixels outside the selection with `mixByMask`). **Lasso fill** (G cycles Fill → Gradient → Lasso fill): fills the drawn shape into the stroke canvas and commits it like a stroke.
  - **Layer lock and reference:** `node.locked` / `node.reference` (layers and folders, saved only when true). `target()` and `beginMove` refuse a node locked itself or by a folder around it (`lockedNode`). Fill and the wand take their area from `sampleData(sample, t)`: 'all' (composite), 'layer', or 'reference' (visible reference layers, or layers in reference folders); the old `sampleAll` tick migrates in `sanitizeSettings`.
  - `js/views/liquifytool.js` with `js/liquify.js`: **Liquify** (J after Smudge, kind `liquify`): Push / Pinch / Bloat / Twirl dabs (`liquifyDab`: each pixel within the radius samples, bilinear and premultiplied, from where the movement came from, weighted by `liquifyFalloff`; `liquifyReach` says how far outside the circle a dab reads). Works like Smudge: straight onto the layer per dab, one patch on pen-up, selection mixed back with `mixByMask`; non-push modes repeat every `HOLD_MS` while the pen is held still. With the symmetry ruler each copy dabs too (push direction from the copy's own step; `symmetryFlips` makes mirrored copies twirl the other way).
  - `js/views/retouchtool.js` with `js/retouch.js`: the **retouch tools** (kind `retouch`): **Blur** (J after Liquify), **Dodge** / **Burn** (O) and **Clone stamp** (S). Like Smudge they change the layer per dab (`mixDab` towards a source patch: `blurredPatch` read with a margin, or `copyRegion` of the clone source; `toneDab` for dodge/burn keeps alpha), keep a pen-down copy and record one patch on pen-up, mixing the selection back with `mixByMask`. Blur/Dodge/Burn follow the symmetry ruler. Ctrl+click sets `this.cloneSrc` ({x, y, offset}); the stroke reads `sampleData(s.sample)` taken at pen-down, so it never copies its own dabs; `aligned` keeps the offset between strokes; `drawCloneOverlay` shows the source.
  - **Layer effects** (`js/effects.js` pure, `js/views/effecttools.js`): a layer's `effects` = {border: {size, color}, shadow: {x, y, blur, color, opacity}} (`sanitizeEffects`, saved only when set). `drawNode` in `composite()` builds the layer (via `layerImage`) for r grown by `effectReach` and draws `effectsImage` (shadow from the paint plus border, then the border) under it; `updateComp` grows every dirty rectangle by `docEffectReach(doc)` so partial redraws still equal full ones. Merge down bakes them in (`effectsCanvas`); Layer → Rasterize layer effects does it on its own. The dialog previews by setting `node.effects` live, then records one `setLayerProp` step.
  - **Colour sliders:** the Color panel's HSV/RGB slider rows (`SLIDER_CHANNELS`, `sliderValues`, `fromSlider`, `sliderStops` in color.js; mode in `koe.colorSliders`).
  - `js/views/gradienttool.js`: the Gradient tool (presets: `GRADIENT_PRESETS` in gradient.js, picked through the Colors choice; Dither runs `ditherData`, doc-anchored triangular noise, once on the stroke canvas at pen-up; Repeat/Mirror: `gradientReach` counts the copies needed to cover the area, `repeatStops` lays them out over one stretched gradient, at most 1000); it fills the stroke canvas (selection bounds or the whole canvas) and commits like a stroke, so opacity, alpha lock, masks and undo behave as for painting.
  - `js/views/texttool.js` with `js/textlayer.js`: **text layers** are ordinary `Layer`s with a `text` object (content, x, y, font, size, bold, italic, align, leading, colour, vertical, outline px and outlineColor hex; the Text tool's `outlineColor` setting is white/black/sub, turned into a hex by `outlineHex`); their pixels are always `renderTextLayer(layer)` of it, and the PNG is saved too. Editing uses a textarea in a `.text-edit` box that carries the view's CSS `matrix()`, so it follows zoom/rotation; its own text is transparent and the layer renders live underneath. Anything that changes a text layer's pixels directly must keep the text in step: `target()` refuses text layers (offering Rasterize) unless `{ read: true }`; the Move tool shifts `text.x/y`; whole-canvas changes, flips and merging into a text layer call `textsIn(rasters)` to drop the text (and restore it on undo). `finishText()` closes an open edit (switching tools, menus, saving, reloading).
  - `js/views/rulertools.js`: edge rulers, guides, perspective ruler (1-3 vanishing points), the grid (`doc.rulers.grid` = {show, size, div, snap}: `drawGrid`, `toggleGrid` Ctrl+', `gridDialog`; showing and settings are saved but not undo steps; grid snapping is its own opt-in because `rulers.snap` defaults on; `gridPoint(dp)` (`snapToGrid`, then `snapToGuides`, which wins) puts the corners of rectangle/ellipse/polygon selections, figures and crops on grid lines and shown guides within `GRID_SNAP_PX`) and stroke snapping, as Editor methods. Ruler edits go through `editRulers(label, fn)` (one undo step, saved in `doc.rulers`); showing/hiding and snap on/off are saved but not undo steps; the edge rulers are a per-machine view setting (`koe.edgeRulers`). Strokes snap via `snapFor()` at pen-down and `snapPoint()` per point: points are held back until the pen has moved `SNAP_PX`, then the candidate line closest to the stroke's direction is picked and every point is projected onto it. **Straight-line and concentric rulers** live in `doc.rulers.shapes` (`{type: 'line', x1, y1, x2, y2}` / `{type: 'ellipse', x, y, rx, ry, angle}`, `sanitizeShape`): a line is a candidate when the stroke starts within `LINE_SNAP_PX` of it; an ellipse always is, as the concentric ellipse through the start (`concentricThrough`, `project` maps points radially in its frame). `pickLine` prefers a guide, grid line or straight ruler the stroke started on when it heads within 30° of it. The Ruler tool drags their handles (`shapeHandles`/`dragShapeHandle`, Shift: 15° steps or a circle) as a `shape` gesture, drags out a new one on empty canvas (`this.rulerMake`, `koe.rulerMake`), and Del removes the picked one (`this.rulerPick`).
  - **Layer colour labels:** `node.label` (one of `LABELS` in `doc.js`, or null), saved with the node, set from the swatch row in the layer panel through `setLayerProp`. **Mask area overlay:** `maskTint()` in `editor.js` draws the active mask (plus the live stroke) in red over the composite while `maskEdit` is on and View → Show mask area (`koe.maskOverlay`) is ticked; it is cached by mask version and `strokeVersion`.
  - Pure, tested modules: `filters.js` (blur via three box blurs on premultiplied planes, sharpen, mosaic, motion blur as a running-sum box blur along parallel pixel lines, zoom/spin blur (`pathBlur`: bilinear samples in the middle of up to 8 equal parts of each streak, later passes 1/8 as long filling the parts; the centre is a % of the canvas, so `apply` also gets the doc size `W, H` and their `margin` is the whole canvas), doc-anchored noise (`noiseAt`), LUT corrections incl. colour balance and Curves (`curvesLut` through `curveAt`; the dialog in `filtertools.js` is a canvas curve editor with a histogram, used when a filter has `curves: true` instead of slider `fields`), HSL, `mixByMask`, `recolor` (Change color to main color: filters with `mainColor: true` get `p.color`), `whiteToAlpha` (Brightness to opacity)), `maskops.js`, `tone.js` (tone sanitizing, density, `applyTone` with equalized spot functions so a density covers that share of the area), `textures.js` (seamless texture tiles), `textlayer.js` layout (`layoutText` with a measure function; vertical text runs in columns right to left), `gradient.js`, `rulers.js` (ruler sanitizing, tick steps, snap candidates/picking/projection, guide hit testing), `tree.js` (layer tree: listing, paths, `destination`/`moveNode` for above/below/top-of/bottom-of, `stepTarget` for the up/down buttons), `canvasmath.js` (anchor offsets, side limits, crop rectangles), `mips.js`, `pixelcache.js`, `transform.js` (free-transform maths: handles, scale about the opposite handle, rotate, hit testing), `brush.js` (pressure, curves, smoothing, stamp spacing), `brushtip.js` (tip masks and texture grays from images), `fill.js` (flood fill, or every matching pixel with `contiguous` off; grow), `history.js` (undo stack with step and memory limits), `view.js` (zoom/rotate/mirror maths), `tools.js` (tool list and settings), `color.js`, `rect.js`, `keys.js`.
  - `js/painter.js`: draws dabs (anti-aliased circles for hard brushes, a pre-rendered gradient tip for soft ones, or a tip image tinted in the brush colour); every tip can be squashed, turned, turned at random and turned with the stroke (`dab(x, y, size, alpha, k)`, k = symmetric copy, so each copy follows its own direction). `registerTip`/`registerTexture` make library images usable as `'img:<id>'`.
  - **Brush library** (`js/views/brushtools.js`, `js/brushtip.js` pure): tip/texture images and saved brushes live in `<app dir>\brushes` (`brushes.json` + `<id>.png`; app.py routes `brushes`, `brushes/image`, `brushes/image/delete`, `brushes/presets`; every change goes through `_change_brushes` under `BRUSH_LOCK` and reads the index strictly, since simultaneous replaces fail on Windows and an unreadable index must never be overwritten with an empty one). Paint tools name images in `tip` / `texture` as `'img:<id>'` (accepted by `applySettings` in `tools.js`); a setting naming a missing image falls back to round / no texture. A preset is `{id, name, settings (BRUSH_KEYS), source}`; the tool remembers it in `preset`. Pressure curves (`sizeCurve`, `flowCurve`: [[x, y]], monotone cubic `curveAt` in `brush.js`) replace `gamma` for their channel; `stampAt(s, p)` gives a stamp's size and density from raw pressure. Per dab, `addStampPoint` adds `dabJitter` (scatter offset, size/density jitter) and `taperIn` (start taper by distance along the stroke) to the stroke's own stamps before `symmetryStamps`, so mirrored copies vary together. Colour jitter (`colorJitter` in brush.js, `shiftColor` in color.js) gives each stamp its own `c` (or, with `colorJitterStroke`, varies `g.color` once at pen-down); `Painter.dab(..., color)` re-tints its tip canvas when the colour changes, and vector lines replay per-dab colours from their seed in `strokeStamps`. Erasers and masks never vary. The end taper (`taperOut`) holds the last `taperOut` px of stamps back in `g.held` (`releaseHeld`, each stamp keeps its distance `d`); `endPaint` scales them by `taperOut(dist - d)` and draws them through `drawStamps`.
  - **Brush import** (`brushimport.py`, route `brushes/import?name=`): `import_brushes(filename, data)` → `{name, brushes: [{name, settings, tip, texture, notes}], images: [{kind, name, png (data URL), white}]}` (tip/texture index into images, so shared images are saved once). **Procreate** `.brush` / `.brushset`: a ZIP with per brush `Brush.archive` (NSKeyedArchiver plist, read with `plistlib` and `_unarchive`; some tools write a plain dict), `Shape.png` (white = paint: `white: True`, turned into a see-through tip by `whiteToAlpha` in the browser before saving) and `Grain.png`; `brushset.plist` gives order and name. Procreate's setting names (`paintSize`, `plotSpacing`, `shapeScatter`, `dynamicsPressureSize`, ...) are undocumented, so every one is optional and range-checked. **Photoshop ABR** v1/v2 (brushes inline) and v6-10 (`8BIM` sections `samp` tips (8/16-bit, raw or PackBits), `patt` patterns in PSD layout, `desc` action descriptor with `Brsh` entries pointing at tips by `sampledData` id and textures by `Txtr.Idnt`). Tips become black PNGs whose alpha is the sample. Photoshop angles turn counter-clockwise (`tipAngle = -Angl`).

### How painting works (keep to this when adding tools)

- A stroke is drawn into the shared **stroke canvas** at full strength; `this.live = {layer, canvas, alpha, mode}` makes `composite()` show it on its layer with the tool's opacity while drawing. On pen-up `commitStroke()` merges it into the layer (`source-over`, `destination-out` for erasing, `source-atop` when the layer's alpha is locked) and records an undo patch of just the changed rectangle. Opacity therefore never builds up within one stroke; density (`flow`) does.
- New paint-like tools should fill the stroke canvas, call `this.sel.clipCanvas(this.strokeCtx, rect)` so the selection is respected, then `commitStroke()`; fills, Delete and Alt+Del with a selection all work this way.
- **Selections** are undo steps (`changeSelection(label, fn)` stores before/after mask snapshots). They are not saved with the artwork.
- **Transform** (`this.xf`): `beginTransform()` lifts the selected pixels (or the whole layer) into `xf.src`, keeps the rest in `xf.base`, and redraws the layer live on every change (`renderTransform`). `applyTransform()` records one undo step for the layer and the selection; `cancelTransform()` puts the pixels back. **Distort** (`startDistort`, or Ctrl+drag a corner) replaces the affine `xf.t` with `xf.quad` (four doc points for the source corners nw, ne, se, sw): `drawWarped` maps `xf.srcData` through `warpImage` (inverse `homography`, bilinear, in transform.js) into the bounds of the quad, redrawn at most once per frame (`setQuad`); the selection mask is warped the same way on apply. While it is active, clicks on the panels/menus apply it first (`finishTransform`), saving waits, and only `onTransformKey` keys work.
- **Layers, folders and masks:** tools never touch `doc.active` directly; they ask `this.target(verb)` for the raster to change. It returns the layer, or its mask while `this.maskEdit` is on, and refuses (with a toast) hidden layers and folders without mask editing. Paint on a target with `this.inkFor(t)` (masks always get black) and `this.strokeMode(t, erase)`. A mask's alpha is how much is **hidden** (Clip Studio Paint style: painting hides, erasing reveals); `composite()` applies it with `destination-out`. Anything that touches every canvas (canvas size, flip canvas) uses `doc.rasters()`, which includes masks; per-node operations use `nodeRasters(node)` (a layer with its mask, or everything in a folder). Known limit: Transform works on one raster (the layer or its mask), not both together; the Move tool moves a layer with its mask.
- Every change goes through the history: pixel changes with `pushPatch(layer, rect, before, after)`, structural changes with `structural(label, do, undo)`. Layer visibility is deliberately not an undo step.
- After any change call `changed(rect)` (or `changed(null)` for everything): it recomposites, redraws, refreshes layer thumbnails and schedules the autosave (800 ms after the last change).
- **Rendering is incremental.** `updateComp(r)` queues region r for recompositing (`this.compQueue`) and adds it to `this.dirty`; `flushComp()` does the compositing once, and runs before anything draws or reads `this.comp` (`render`, the eyedropper, `sampleData`, the Navigator), so several pointer moves in one frame cost one composite. Call `flushComp()` before any new reader of `this.comp`; `requestRender()` draws once per frame and `render(region)` repaints only the whole screen pixels that region covers (clip snapped to device pixels, so no anti-aliased edges blend twice). The background, paper shadow, white paper and checker depend only on the view and live in `this.paperLayer` (drawn by `drawPaperLayer` on full renders, copied for partial ones). A partial redraw must equal a full one pixel for pixel; `setView` and `resize` do full renders. `drawOverlay()` only schedules `paintOverlay()` for the next frame, so pointer moves cost one overlay redraw per frame; layer thumbnails refresh at most every 150 ms. The composite canvas has no `willReadFrequently` (it is drawn every frame and read rarely).
- Saving re-encodes only layers whose `version` changed (`Layer.toPng`). Raise `layer.touch()` after changing its pixels.
- **Never read GPU canvases in the hot path.** Layers, the composite and the stroke canvas live on the GPU; `getImageData` on any of them makes the browser finish all queued drawing first (it cost 0.5-1.4 s at every pen-up and a stall per dab). So: `commitStroke` keeps undo copies with `snapshot(layer, r)` (a GPU canvas copy; `readSnapshots` turns them into ImageData when idle; `pushPatch` takes either); tools that change pixels dab by dab (Smudge, Liquify, the retouch tools) read and write through a `PixelCache` (`pixelcache.js`, via `directpaint.js`: tiles read once when first touched, changed tiles written back per pointer move, the first-read pixels kept for the undo step, `endDirect` at pen-up). New dab-by-dab tools should do the same. Note: reading the same untouched GPU canvas twice can give values 1 apart on semi-transparent pixels (the browser moves it to memory after the first read), so compare pixels only after a first read.
- **Zoomed out, the screen is drawn from `this.mips`** (the composite at 1/2, 1/4, ...; `mips.js`): `updateMips(n)` redraws only `this.mipDirty` (set by `flushComp`) in each level with plain bilinear halving, and `render`/the Navigator draw the level from `mipLevel(scale)` with `imageSmoothingQuality = 'low'`. Never draw the composite downscaled with 'high' or 'medium' quality: the browser then rebuilds mipmaps of the whole composite on every change (20 ms frames and 100+ ms hitches on a 3000 x 2000 canvas). Anything that replaces `this.comp` resets `this.mips = [this.comp]`.

### Conventions

- **Save format:** add new fields with a default in `sanitizeDoc` so old `.koe` files keep loading. Never break old files; bump `FORMAT_VERSION` and convert if a field changes shape. Version 2 (folders, masks, `activePath`) reads version 1 files (flat `layers`, `active` index) unchanged.
- **Escaping:** use `esc()` for anything user-supplied that goes into HTML.
- **Storage:** `store(key, value)` in `ui.js` wraps `localStorage` (`koe.` prefix) and never throws.
- **Shortcuts:** follow Clip Studio Paint where it has a convention (P pen, B brush, E eraser, G fill, M selection, W magic wand, U ruler, I eyedropper, H hand, Space pan, Alt eyedropper, Q quick mask, [ ] size, X swap colours, Ctrl+T transform, Ctrl+2 snap to rulers). Ctrl+R stays the reload key.
- **Tools sharing a key:** give them the same `key` in `TOOLS`; repeated presses take turns (`toolForKey`), as G does for Fill and Gradient.
- **UI layout:** the tool bar is grouped by `group` in `TOOLS` (a separator between groups). The **Tool property panel** (`.ed-left`, next to the tool bar) shows the current tool's settings, one compact row each (label | slider | value); for paint tools it shows only `BASIC_PAINT` plus a **Brush settings…** button; the floating Brush settings window (`renderBrushWindow` in `brushtools.js`, state in `koe.brushWin` = {open, x, y, page}) has a page per `SETTING_GROUPS` entry (Paint, Tip, Pen pressure, Stroke, Variation, Texture) under a stroke preview (`drawBrushPreview`: `previewPath`/`previewSettings` in brush.js, dabs from vector.js `strokeStamps` with a fixed seed, so the preview is the real pipeline; redrawn on every setting or colour change). The Gradient tool's panel starts with a colour strip (`drawGradientStrip`). Both are built by `settingsHtml`/`bindSettings` in `editor.js`; `showSetting(k)` copies a changed value into the other one, and `renderToolProps()` redraws both. Other tools get one flat list. Keep labels short and put the explanation in `SETTING_HINTS` (shown as a tooltip). The right side holds Color and Layers. Side panels fold by clicking their heading (`koe.folded`). Menu items with `checked` get a tick column. The `[hidden]` attribute is forced to `display: none` in `app.css`, because button styles would otherwise override it. Tool keys live in `TOOLS`; the rest in `onKey`.
- **Icons:** add SVG paths to `icons.js`. The app icon is a chubby cow ("koe") holding a paint palette and brush, drawn in `tools/icon.svg` in the style of the user's BiggTaal and Varken Sketchpad pigs (soft flat shapes, no tile, same eyes and cheeks); `tools/make_icon.mjs` renders it through headless Edge into `web/icon.ico` (PNG entries, 16-256) and `web/icon.png`. The window, taskbar, shortcuts and `.koe` files use `web/icon.ico`; the launcher embeds it.
- **Guide:** a new or changed feature also gets a line in the right page of `GUIDE` in `js/guide.js` (Help → Guide, F1), and a new shortcut goes in `SHORTCUTS` there (tool keys are listed from `TOOLS` by themselves). Plain words, short sentences, numbered steps for how-tos, a `tip` paragraph for the one thing worth remembering, and a picture (`guidepics.js`) where seeing it explains it faster than words.

## Gotchas

- Port 8790 can already belong to another program on this PC (it once answered with a different app's page). The server then moves to the next free port and prints the URL (`Serving http://127.0.0.1:<port>/`); read that line instead of assuming the port, and check `/api/config` answers with `artDir` before testing.
- Editing files that contain backslashes (`.ps1`, docs with Windows paths) through a Python string in a shell heredoc silently turns `\r`, `\t`, `\x` and similar into control characters. Use the Edit tool, or build backslashes with `chr(92)`, and re-read the result.
- Use `127.0.0.1`, not `localhost` (IPv6-first lookup makes every request slower).
- The pywebview window keeps localStorage in `%LOCALAPPDATA%\KoeStudio\webview` (`private_mode=False`); without it tool settings are forgotten each launch.
- `setPointerCapture` throws for pointers the browser no longer tracks; keep it in a `try`.
- Big canvases are memory-heavy: one 4000×4000 layer is 64 MB, and every full-layer undo step holds two copies. `History` drops old steps past 600 MB.
