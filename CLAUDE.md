# KoeStudio

Windows desktop drawing and painting program, aiming to be a full-purpose tool in the spirit of Clip Studio Paint. See README.md for the user-facing feature list and the roadmap below for what comes next.

## Workflow (follow this in every session)

- **Runs straight from this folder.** The Desktop and Start-menu shortcuts (`KoeStudio.lnk`) and `Run KoeStudio.lnk` start `pythonw app.py` from the project folder. There is no installer and no build step for day-to-day use: every saved change is live the next time the app is opened, or straight away after a reload.
- **Reload key:** F5 or Ctrl+R in any screen saves pending work, then reloads the page so edited `web/` files take effect (`reload()` in `js/app.js`; the open screen and artwork are remembered in `sessionStorage`). Changes to `app.py` need the app restarted.
- **The user's data lives outside the project folder.** Artwork: `Pictures\KoeStudio` (`<id>.koe`, `.thumbs/`, `.deleted/`, `Exports/`). Window storage (tool settings, colours) and `error.log`: `%LOCALAPPDATA%\KoeStudio`. Never write user data into the project.
- **Never build installers or release packages (nothing for others to install), and never publish a GitHub release, unless the user asks.** The committed `KoeStudio.exe` launcher is not one of these: it just starts `app.py`. Finish changes in source, run the tests, and commit.
- **Testing must not disturb the user:**
  - **Nothing pops up on the desktop.** Test the UI with `python app.py --browser` in Claude's built-in browser pane, or start the real window with `--hidden` (never shown). Don't launch the visible app while testing.
  - **Sound is muted.** Always start test runs with `KOE_MUTE=1` (or `--muted`). `js/mute.js` then silences every audio entry point (media elements, Web Audio, speech), so it also covers sound code added later. Any new sound must still play through the normal browser APIs so the mute catches it.
  - **Scratch data only.** Point test runs at a scratch folder, never the real `Pictures\KoeStudio`:
    `KOE_ART_DIR=<scratch>/art KOE_APP_DIR=<scratch>/app KOE_MUTE=1 KOE_PORT=8790 python app.py --browser`
  - **Looking at the UI:** `node tools/ui_shot.mjs <url> <steps.mjs> <out-folder> [w] [h]` drives a headless, muted Edge over the DevTools protocol and saves screenshots; nothing appears on the desktop. The steps module gets `evaluate(js)`, `shot(name)`, `wait(ms)`, `navigate(url)`. Keep step scripts and screenshots in the scratchpad, point the URL at a scratch test server, and read the PNGs to check layout changes before calling UI work done.
  - When the browser pane is hidden it may not paint or fire ResizeObserver, and its viewport can be 0×0. Give the tab a size with `resize_window` (e.g. 1400×900, reset to `desktop` afterwards), reload, drive it with `javascript_tool` (dispatch `PointerEvent`/`KeyboardEvent`; after Ctrl+0 the view is `zoom = min((vw-80)/W, (vh-80)/H)`, centred) and check results through the saved files (`.thumbs/<id>.png`).
- **`.koe` double-click:** `tools\register_koe.ps1` registers the `.koe` type for the current user (`-Remove` undoes it). Explorer then runs `pythonw app.py "<file>"`; `app.py` queues it in `PENDING_OPEN`, `config` reports `openFile`, and `js/app.js` takes it from `GET open-file` (handed out once) and opens it as a new artwork, like Open image or project…. Each launch is its own window. `KoeStudio.exe` (committed prebuilt; its small C# source was deleted on purpose, so write a new one if it is ever lost) is a tiny launcher that finds `pythonw.exe` at start and runs `app.py <args>` next to it, so Windows lists KoeStudio in Open with. `register_koe.ps1` points the association at it and adds an `Applications\KoeStudio.exe` entry. Rerun `register_koe.ps1` if the folder moves.
- If the folder or Python moves, recreate the shortcuts with `powershell -ExecutionPolicy Bypass -File tools\make_shortcut.ps1` (`-LocalOnly` makes only the one in the project folder).

## Architecture

- **`app.py`**: stdlib `ThreadingHTTPServer` on 127.0.0.1 (port 8770, or the next free one) serving `web/` and a small JSON API, shown in a pywebview (WebView2) window. Flags: `--browser` (serve only), `--hidden` (window never shown), `--muted`. Env: `KOE_ART_DIR`, `KOE_APP_DIR`, `KOE_PORT`, `KOE_MUTE`.
  - `Handler._allowed` refuses requests from other web pages (foreign `Host`, foreign `Origin`, `Sec-Fetch-Site` cross-site/same-site).
  - Static files are sent `Cache-Control: no-cache` (revalidated, so a reload picks up edits); API answers `no-store`.
  - API: `config`, `art` (list), `art/file`, `art/thumb`, `art/save` (new id when none given), `art/delete` (moves to `.deleted/`), `export` (PNG to `Exports/`, never overwrites), `open-folder`.
- **`web/`**: vanilla ES modules, no framework, no build step. Edit and reload.
  - `js/app.js`: start-up (mute, reload key) and switching between gallery and editor.
  - `js/imageformats.js`: export formats (`EXPORT_FORMATS`) and pure TGA/BMP/GIF encoders (median-cut palette + LZW); PNG/JPEG/WebP come from `canvas.toBlob`. `exportAs(format)` in `editor.js` posts to `export?format=`; `app.py` `export_image` checks the file signature per format.
  - `js/views/gallery.js`: artwork cards, New canvas dialog (`PRESETS`), Open image.
  - `js/views/editor.js`: the drawing screen. Viewport (`render`, `updateComp`), pointer input, painting, undo, autosave, menus and shortcuts (`onKey`). Feature groups live in mixins assigned to `Editor.prototype`: `layerops.js`, `selecttools.js`, `canvasops.js`.
  - `js/views/colorpanel.js`, `js/views/layerpanel.js`: side panels. They change the document only through editor methods. The layer panel draws `panelRows()` (top first, indented), handles click-to-select (the mask thumbnail selects mask editing) and drag-and-drop (`moveNodeTo`).
  - `js/doc.js`: `Doc` with a layer **tree** (`doc.root`, a `Folder`; `doc.active` is the selected node), `Layer` and `Mask` (both rasters: canvas, `version`, cached PNG), `Folder`, `cloneNode`, `nodeRasters`, `composite()` (paper, folders, "Through" pass-through, blend modes, opacity, clipping groups, masks, the live stroke), save format and `sanitizeDoc`.
  - `js/views/layerops.js`: everything that changes the tree (add, folder, Put in new folder, duplicate, delete, move/step, merge down, merge folder, properties), masks (add/apply/delete/toggle, mask editing), and the current-layer pixel operations (Move tool, clear, fill, flip).
  - `js/views/selecttools.js`: selection tools (rectangle, ellipse, lasso, polygon, magic wand), selection commands (incl. expand/shrink/feather via `Selection.morph`/`feather`), copy/cut/paste and free transform, as methods mixed into `Editor.prototype`. The polygon tool keeps its corners in `this.poly` between clicks (no gesture); `changeSelection` and `selectTool` drop it, `onPolygonKey` handles Enter/Esc/Backspace.
  - `js/views/filtertools.js` with `js/filters.js`: the **Filter menu**. `FILTERS` lists each filter with its dialog sliders, `margin(params)` (how far it reads outside the area, so blurs at a selection edge see their surroundings) and `apply(data, w, h, params, x0, y0)`. `runFilter` takes `target()` (layer or mask), snapshots the whole raster, previews on every slider change (`previewFilter`: filter the area + margin, `mixByMask` with the selection's alpha, put back) in a non-dimming `modal({ live: true })` at the bottom, and on OK records one `pushPatch` for the selection bounds; Cancel restores the snapshot. Add a filter by adding an entry to `FILTERS` with a pure function and a test.
  - `js/selection.js`: `Selection`, a doc-sized mask canvas with bounds and an outline for the marching ants; `combine(mode, draw)` adds/subtracts/intersects a shape; `clipCanvas(ctx, rect)` cuts a canvas down to it; `morph`/`feather` go through `alphaPlane()`/`setAlphaPlane()` and `maskops.js` (chamfer 3-4 distance transform for expand/shrink, Gaussian blur for feather; the canvas edge counts as outside when shrinking).
  - `js/views/canvasops.js`: canvas size, image size, crop (tool and to selection), rotate canvas, as Editor methods. All go through `reshapeCanvas(label, w, h, paint)`, which gives every layer a new canvas and records one undo step that swaps the old canvases back (`setCanvasState` also resizes the composite/stroke canvases, resets the selection and fits the view). Use it for any future change of canvas size.
  - **Brush textures** (`textures.js` tiles, `textureFor(s)` in `painter.js`): paint tools set `live.texture = {tile, scale}`; the stroke canvas itself stays untextured and `liveSource(live, r)` in `doc.js` cuts the grain out of a scratch copy whenever the stroke is shown or committed, so the grain is applied once per stroke (never compounding) and stays anchored to the doc. Anything that draws `live.canvas` must go through `liveSource`.
  - **Screentone** (`tone.js`, `js/views/tonetools.js`): a layer with `tone` ({cell, angle, shape, color}) keeps its gray pixels; `drawNode` in `composite()` turns the region being drawn into dots (`applyTone`, grid anchored to the doc), so thumbnails show gray but the canvas, flatten and export show dots. Merge down and Rasterize screentone use `tonedCanvas(layer)`.
  - `js/views/figuretool.js` with `js/figure.js`: the **Figure tool** (line, rectangle, ellipse; Shift constrains). The outline points come from `figurePoints`, the shape is re-stamped into the stroke canvas on every move (`figureDraw`) and committed with `commitStroke`. `linePoints` also serves Shift+click straight strokes in `beginPaint` (from `this.lastStroke`).
  - `js/views/gradienttool.js`: the Gradient tool; it fills the stroke canvas (selection bounds or the whole canvas) and commits like a stroke, so opacity, alpha lock, masks and undo behave as for painting.
  - `js/views/texttool.js` with `js/textlayer.js`: **text layers** are ordinary `Layer`s with a `text` object (content, x, y, font, size, bold, italic, align, leading, colour, vertical); their pixels are always `renderTextLayer(layer)` of it, and the PNG is saved too. Editing uses a textarea in a `.text-edit` box that carries the view's CSS `matrix()`, so it follows zoom/rotation; its own text is transparent and the layer renders live underneath. Anything that changes a text layer's pixels directly must keep the text in step: `target()` refuses text layers (offering Rasterize) unless `{ read: true }`; the Move tool shifts `text.x/y`; whole-canvas changes, flips and merging into a text layer call `textsIn(rasters)` to drop the text (and restore it on undo). `finishText()` closes an open edit (switching tools, menus, saving, reloading).
  - `js/views/rulertools.js`: edge rulers, guides, perspective ruler (1-3 vanishing points) and stroke snapping, as Editor methods. Ruler edits go through `editRulers(label, fn)` (one undo step, saved in `doc.rulers`); showing/hiding and snap on/off are saved but not undo steps; the edge rulers are a per-machine view setting (`koe.edgeRulers`). Strokes snap via `snapFor()` at pen-down and `snapPoint()` per point: points are held back until the pen has moved `SNAP_PX`, then the candidate line closest to the stroke's direction is picked and every point is projected onto it.
  - **Layer colour labels:** `node.label` (one of `LABELS` in `doc.js`, or null), saved with the node, set from the swatch row in the layer panel through `setLayerProp`. **Mask area overlay:** `maskTint()` in `editor.js` draws the active mask (plus the live stroke) in red over the composite while `maskEdit` is on and View → Show mask area (`koe.maskOverlay`) is ticked; it is cached by mask version and `strokeVersion`.
  - Pure, tested modules: `filters.js` (blur via three box blurs on premultiplied planes, sharpen, mosaic, LUT corrections, HSL, `mixByMask`), `maskops.js`, `tone.js` (tone sanitizing, density, `applyTone` with equalized spot functions so a density covers that share of the area), `textures.js` (seamless texture tiles), `textlayer.js` layout (`layoutText` with a measure function; vertical text runs in columns right to left), `gradient.js`, `rulers.js` (ruler sanitizing, tick steps, snap candidates/picking/projection, guide hit testing), `tree.js` (layer tree: listing, paths, `destination`/`moveNode` for above/below/top-of/bottom-of, `stepTarget` for the up/down buttons), `canvasmath.js` (anchor offsets, side limits, crop rectangles), `transform.js` (free-transform maths: handles, scale about the opposite handle, rotate, hit testing), `brush.js` (pressure, smoothing, stamp spacing), `fill.js` (flood fill, grow), `history.js` (undo stack with step and memory limits), `view.js` (zoom/rotate/mirror maths), `tools.js` (tool list and settings), `color.js`, `rect.js`, `keys.js`.
  - `js/painter.js`: draws dabs (anti-aliased circles for hard brushes, a pre-rendered gradient tip for soft ones).

### How painting works (keep to this when adding tools)

- A stroke is drawn into the shared **stroke canvas** at full strength; `this.live = {layer, canvas, alpha, mode}` makes `composite()` show it on its layer with the tool's opacity while drawing. On pen-up `commitStroke()` merges it into the layer (`source-over`, `destination-out` for erasing, `source-atop` when the layer's alpha is locked) and records an undo patch of just the changed rectangle. Opacity therefore never builds up within one stroke; density (`flow`) does.
- New paint-like tools should fill the stroke canvas, call `this.sel.clipCanvas(this.strokeCtx, rect)` so the selection is respected, then `commitStroke()`; fills, Delete and Alt+Del with a selection all work this way.
- **Selections** are undo steps (`changeSelection(label, fn)` stores before/after mask snapshots). They are not saved with the artwork.
- **Transform** (`this.xf`): `beginTransform()` lifts the selected pixels (or the whole layer) into `xf.src`, keeps the rest in `xf.base`, and redraws the layer live on every change (`renderTransform`). `applyTransform()` records one undo step for the layer and the selection; `cancelTransform()` puts the pixels back. While it is active, clicks on the panels/menus apply it first (`finishTransform`), saving waits, and only `onTransformKey` keys work.
- **Layers, folders and masks:** tools never touch `doc.active` directly; they ask `this.target(verb)` for the raster to change. It returns the layer, or its mask while `this.maskEdit` is on, and refuses (with a toast) hidden layers and folders without mask editing. Paint on a target with `this.inkFor(t)` (masks always get black) and `this.strokeMode(t, erase)`. A mask's alpha is how much is **hidden** (Clip Studio Paint style: painting hides, erasing reveals); `composite()` applies it with `destination-out`. Anything that touches every canvas (canvas size, flip canvas) uses `doc.rasters()`, which includes masks; per-node operations use `nodeRasters(node)` (a layer with its mask, or everything in a folder). Known limit: Transform works on one raster (the layer or its mask), not both together; the Move tool moves a layer with its mask.
- Every change goes through the history: pixel changes with `pushPatch(layer, rect, before, after)`, structural changes with `structural(label, do, undo)`. Layer visibility is deliberately not an undo step.
- After any change call `changed(rect)` (or `changed(null)` for everything): it recomposites, redraws, refreshes layer thumbnails and schedules the autosave (800 ms after the last change).
- **Rendering is incremental.** `updateComp(r)` recomposites region r and adds it to `this.dirty`; `requestRender()` draws once per frame and `render(region)` repaints only the whole screen pixels that region covers (clip snapped to device pixels, so no anti-aliased edges blend twice). The background, paper shadow, white paper and checker depend only on the view and live in `this.paperLayer` (drawn by `drawPaperLayer` on full renders, copied for partial ones). A partial redraw must equal a full one pixel for pixel; `setView` and `resize` do full renders. `drawOverlay()` only schedules `paintOverlay()` for the next frame, so pointer moves cost one overlay redraw per frame; layer thumbnails refresh at most every 150 ms. The composite canvas has no `willReadFrequently` (it is drawn every frame and read rarely).
- Saving re-encodes only layers whose `version` changed (`Layer.toPng`). Raise `layer.touch()` after changing its pixels.

### Conventions

- **Save format:** add new fields with a default in `sanitizeDoc` so old `.koe` files keep loading. Never break old files; bump `FORMAT_VERSION` and convert if a field changes shape. Version 2 (folders, masks, `activePath`) reads version 1 files (flat `layers`, `active` index) unchanged.
- **Escaping:** use `esc()` for anything user-supplied that goes into HTML.
- **Storage:** `store(key, value)` in `ui.js` wraps `localStorage` (`koe.` prefix) and never throws.
- **Shortcuts:** follow Clip Studio Paint where it has a convention (P pen, B brush, E eraser, G fill, M selection, W magic wand, U ruler, I eyedropper, H hand, Space pan, Alt eyedropper, [ ] size, X swap colours, Ctrl+T transform, Ctrl+2 snap to rulers). Ctrl+R stays the reload key.
- **Tools sharing a key:** give them the same `key` in `TOOLS`; repeated presses take turns (`toolForKey`), as G does for Fill and Gradient.
- **UI layout:** the tool bar is grouped by `group` in `TOOLS` (a separator between groups). The **Tool property panel** (`.ed-left`, next to the tool bar) shows the current tool's settings, one compact row each (label | slider | value); for paint tools the rows are grouped by `SETTING_GROUPS` in `tools.js` (Brush, Pen pressure, Stroke, Texture), other tools get one flat list. Keep labels short and put the explanation in `SETTING_HINTS` (shown as a tooltip). The right side holds Color and Layers. Side panels fold by clicking their heading (`koe.folded`). Menu items with `checked` get a tick column. The `[hidden]` attribute is forced to `display: none` in `app.css`, because button styles would otherwise override it. Tool keys live in `TOOLS`; the rest in `onKey`.
- **Icons:** add SVG paths to `icons.js`; `tools/make_icon.py` makes the app icon.

## Gotchas

- Use `127.0.0.1`, not `localhost` (IPv6-first lookup makes every request slower).
- The pywebview window keeps localStorage in `%LOCALAPPDATA%\KoeStudio\webview` (`private_mode=False`); without it tool settings are forgotten each launch.
- `setPointerCapture` throws for pointers the browser no longer tracks; keep it in a `try`.
- Big canvases are memory-heavy: one 4000×4000 layer is 64 MB, and every full-layer undo step holds two copies. `History` drops old steps past 600 MB.

## Roadmap (not built yet)

Text: per-character styling, outlines/shadows, speech balloons, text on transform without rasterizing. Gradient: multi-stop presets, repeat/mirror, dithering. Rulers: straight-line, curve, symmetry and concentric-circle rulers, a grid, guides that follow crops and canvas resizes, snapping selections and shapes to guides. Figure extras (polyline, curve, polygon, rounded corners), selection extras (selection painting / quick mask, select by colour range, border), perspective and mesh transform; resolution (dpi) setting; linked transform of layer + mask, layer multi-select; vector/line layers; custom brush tips; screentone extras (dpi-based lines per inch, per-layer tone offset, gradient tone presets); more filters (motion/radial blur, noise, line extraction, colour balance, curves, liquify) and a repeat-last-filter shortcut; two-finger touch gestures; reference window; PSD import/export; per-layer files for faster saves on huge canvases; animation timeline.
